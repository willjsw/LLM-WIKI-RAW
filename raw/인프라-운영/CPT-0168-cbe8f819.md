# MDC 로그 컨텍스트의 정리와 스레드 경계

## Definition

MDC(Mapped Diagnostic Context)는 현재 스레드에 키-값을 붙여 그 스레드의 모든 로그에 자동으로 포함시키는 장치다. 스레드에 묶여 있으므로 요청 처리가 끝나면 넣은 값을 제거해야 하고, 다른 스레드에서 실행되는 콜백에는 값이 자동으로 따라가지 않는다.

## Evidence

- 리뷰에서 RPC 요청 처리가 끝난 뒤 `MDC.remove("rpc_info")` 로 요청 정보를 제거하도록 했다. 지우지 않으면 스레드가 재사용될 때 이전 요청 값이 다음 로그에 섞인다.
- 이벤트 처리 후 MDC Clear 가 필요하다는 지적이 있었다.
- gRPC 스트림의 `onNext` 가 별도 스레드에서 실행되면 MDC 값이 제대로 찍히지 않을 것이라는 우려가 제기됐다(검증 결과는 기록에 없음). 이런 경우 콜백 진입 시 컨텍스트를 복사해 넣고 끝날 때 지우는 처리가 필요하다.
- 공통 식별자(예: 통화의 Call ID)는 외부 인터페이스뿐 아니라 내부 호출 메서드의 로그에도 남아 있어야 추적이 이어진다.
- 요청 로그가 Request 시점에 남지 않고 Response 이후에만 남는 문제가 있었다. AOP 로깅 지점과 MDC 설정 시점을 맞춰야 한다.
