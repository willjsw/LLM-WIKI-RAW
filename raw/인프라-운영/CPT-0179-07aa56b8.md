# 로그 마스킹과 저장 데이터 암호화의 구분

## Definition

마스킹은 값을 되돌릴 수 없게 가리는 처리이고, 암호화는 키로 원문을 되돌릴 수 있게 감추는 처리다. 로그처럼 원문이 다시 필요 없는 곳은 마스킹, DB 저장 데이터처럼 업무에 원문이 다시 필요한 곳은 암호화를 적용한다.

## Evidence

- 적용 범위를 DB 저장 데이터는 암호화, 로그는 마스킹으로 나눴다.
- 민감정보는 최초 인입 지점에서 암호화하고, 각 서버는 민감정보를 파일 로그로 남기지 않는다. 서버 간 전송과 메시지 큐(Redis Stream) 메시지도 암호화 대상이다.
- 키-값 로그를 수집하는 경우 값만 암호화하고, 암호화된 필드에 형식 표시를 남겨 사람이 구분할 수 있게 한다는 안이 있었다.
- 브라우저(FE)에는 암호화 키를 두지 않는다. 전송 구간은 TLS로 보호하고 암복호화는 백엔드가 맡는다.
- 가장 좋은 방법은 고객 정보를 애초에 저장하지 않는 것이다.
- 전문 길이 제한이 있는 구간(예: 교환기 전달 필드)은 암호문이 길어져 다른 데이터를 못 실을 수 있으므로 중복 필드를 정리해야 한다.
