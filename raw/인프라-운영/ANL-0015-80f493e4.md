# AWS 를 파트너 경유 통합 빌링으로 쓸 때 확인할 점

## Analysis

AWS 를 직접 계약하지 않고 파트너(리셀러·MSP)를 통해 결제하거나 운영을 맡길 때, 한 제안 미팅에서 확인된 항목을 일반화해 점검 목록으로 정리했다. 구체 조건은 파트너마다 다르므로 계약 전 확인이 필요하다.

1. **계약 형태 선택 기준**: 내부에 AWS 운영 인력이 있으면 결제만 파트너를 거치는 빌링 계약(인프라 제어는 고객), 없거나 24시간 운영이 필요하면 유상 관리형 서비스. 관리형은 보통 월 사용료 비례 요금과 최소 청구액이 붙는다.
2. **비용 가시성**: 통합 빌링으로 묶이면 AWS Cost Explorer 를 직접 쓰지 못하고 파트너 도구로 본다. 반영 지연(며칠)과 약정 할인(RI·Savings Plans) 관련 지표가 가려지는지 확인한다.
3. **권한 경계**: 루트 계정은 고객이 보유하고, 파트너에는 고객이 만든 IAM 사용자·키로 최소 권한만 위임하는 구조인지 확인한다.
4. **지원 경로**: AWS Basic Support 는 계정·빌링 문의만 가능하다. 파트너 경유 시 기술 지원 경로와 Support Plan 등급 변경 절차(콘솔 직접 변경 불가 여부)를 확인한다.
5. **마이그레이션 지원 범위**: 인프라·네트워크까지인지, 애플리케이션 이전까지인지, IaC 산출물을 주는지 명확히 한다. 콘솔 수동 구축만 받으면 이후 재현·변경 관리가 어렵다.
6. **모니터링 도구**: 파트너 자체 에이전트를 쓰기 전에 CloudWatch Agent 로 충족되는지 비교하고, 매니지드 서비스 지표 수집 시 CloudWatch API 비용을 고려한다.
