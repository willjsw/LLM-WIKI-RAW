# 애플리케이션 로그 민감정보 마스킹 구현

## Purpose

로그에 전화번호, 이메일, 자격증명 같은 민감정보가 남지 않도록 출력 직전 한 지점에서 비가역으로 치환한다.

## Steps

1. 마스킹 대상 패턴을 정의한다. 자유 텍스트용 정규식(전화번호, 이메일, 주민번호, `password|token|api_key` 뒤의 값 등)과 구조화 로그용 민감 키 목록(password, token, api_key, authorization 등)을 따로 둔다.
2. 마스킹 함수를 호출부마다 부르지 말고 로깅 프레임워크에 결합한다. Python은 `logging.Filter`에서 `record.msg`와 `record.args`를 치환하고, Logback은 PatternLayout replace나 커스텀 Converter, pino는 `redact` 경로 옵션을 쓴다.
3. JSON 같은 구조화 로그는 키 이름 기준으로 값을 재귀 치환한다. 정규식보다 오탐·미탐이 적다.
4. 키 기반과 정규식을 함께 적용한다(구조화 필드는 키, 메시지 본문은 정규식).
5. 적용 위치는 로그가 디스크나 외부 수집기로 나가기 직전 마지막 지점 한 곳으로 둔다. 여러 곳에 흩어 두면 일부 경로에서 빠진다.
6. 마스킹은 비가역으로 한다. 복호화 가능한 형태로 남기면 로그 저장소가 새 유출 지점이 된다.
