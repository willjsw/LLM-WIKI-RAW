# 콜 테스트 검증 축 분리 이벤트 콜 단위 통계 집계

## Definition

콜 회귀 결과를 축 1 이벤트(소켓 이벤트 ↔ DB 이벤트), 축 2 콜 단위 통계, 축 2 집계(시간 버킷 뷰), 축 3 노드 뷰로 나눠 따로 판정한다. 가장 가치 있는 결과는 '축 1 PASS + 축 2 FAIL', 곧 콜은 정상인데 통계가 틀린 경우다.

## Evidence

- 이벤트 비교는 같은 초 안의 순서를 무시하는 다중집합 비교로 한다. 판정은 유형별로 나눈다. 필수 누락·금지 존재·개수 불일치는 FAIL_FUNCTIONAL, 시간 범위 밖은 FAIL_TIMING, 소켓에만 있으면 FAIL_DB_LOST, DB 에만 있으면 FAIL_PUSH_LOST 다.
- 같은 이유로 3번 연속 실패하면 개별 케이스가 아닌 공통 장애로 보고 중단한다.
- 통계 행이 0건이면 파이프라인이 콜 종료 시각까지 적재했는지(freshness)를 확인한다. 아직이면 FAIL 이 아니라 SKIP_NOT_LOADED 로 둔다.
- 기대값 검사, 정답지(검수된 콜 1통 기준으로 개수 칸은 일치, 시간 칸은 참고), 베이스라인 회귀(골든 런과 전 컬럼 비교, 시간 칸만 ±3초 허용)를 구분한다.
- 콜 ID 가 없는 케이스는 테스트 로그 시각 기준의 시간 창 안에서 시작된 세션이 정확히 1건일 때만 자동 선택하고, 2건 이상이면 사람이 지정한다.
