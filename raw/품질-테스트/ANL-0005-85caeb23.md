# 콜 자동 테스트 1세대 구성의 취약점 분석

## Analysis

코드 리딩으로 확인한 1세대 콜 자동 테스트의 취약점과, 다른 통합 테스트에도 적용할 교훈이다. 실행 결과로 검증한 것이 아니므로 확인이 더 필요하다.

- 고정 sleep 대기: Ready 대기를 5초 고정으로 두어 로그인이 늦으면 콜이 Ready 전에 도착할 수 있다. 상태 이벤트를 기다리는 조건 대기로 바꿔야 한다.
- 문자열 판정: 로그 문구 grep 으로 PASS/FAIL 을 판정해 포맷이 바뀌면 전부 UNKNOWN 이 된다. 구조화 결과 레코드로 판정해야 한다.
- 로그 덮어쓰기: 파일명에 타임스탬프가 없어 재실행 시 이전 결과가 사라져 회귀 비교가 어렵다.
- 정의 이원화: 같은 케이스를 두 스크립트·두 파일에 정의하면 동작이 같은지 보장할 수 없다. preflight 는 누락은 막아도 내용 불일치는 못 잡는다. 정본을 하나로 둔다.
- 메모와 실제 필드 불일치: 메모에만 값이 있고 필드가 없어 기본값이 적용되거나, 계산할 수 없는 문자열 값이라 항상 SKIP 되는 케이스가 있었다. 해석 실패는 SKIP 이 아니라 명시적 오류로 드러내야 한다.
- 케이스 간 격리 없음: 한 케이스가 자원(상담사)을 묶으면 뒤 케이스가 연쇄 실패한다. 케이스 시작 전 자원 상태 초기화나 확인이 필요하다.
- 시간 버킷 조회: 버킷 전체를 가져오면 다른 케이스·운영 데이터가 섞여 케이스별 판정에 쓸 수 없다.
