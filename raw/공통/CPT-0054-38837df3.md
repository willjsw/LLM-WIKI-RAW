# 컨테이너 오케스트레이터가 대신해 주는 네 가지 기능

## Definition

컨테이너 오케스트레이터(Docker Swarm, Kubernetes)를 도입하는 목적은 프로세스 이중화, 프로세스 감시·자동 복구, 노드 장애에 대비한 서비스 이중화, 로드밸런싱 네 가지로 정리된다. 오케스트레이터를 쓸 수 없으면 이 기능을 개별 도구로 다시 채워야 한다.

## Evidence

- 베어메탈 대체 구성: 프로세스 감시·자동 복구는 supervisord, 로드밸런싱은 HAProxy, 앞단 분산은 L4 스위치가 맡는다(`GW → HAProxy → 서비스들`)
- Docker Swarm은 내장 DNS와 namespace로 서비스 디스커버리와 통신을 처리한다
- Kubernetes를 직접 설치하면 컨테이너 런타임(containerd), kubectl/kubelet/kubeadm, Pod 간 통신용 CNI 플러그인, 네트워크 스토리지용 StorageClass가 필요하고 namespace 단위로 파일시스템·네트워크를 분리한다
