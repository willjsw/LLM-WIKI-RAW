# PARA 분류 기준과 Project와 Area 판별 질문

## Definition

PARA 는 노트를 Projects(종료 조건이 명확한 작업)·Areas(종료 없이 계속 맡는 책임)·Resources(다른 작업에서도 다시 꺼내볼 레퍼런스)·Archives(더 이상 능동적으로 다루지 않는 자료) 네 범주로 나누는 분류법이다. Project 와 Area 는 "이게 끝나는 시점이 언제냐?"에 답할 수 있는지로 가른다.

## Evidence

- 답할 수 있으면 Project(예: 특정 납기까지 기능 완료), 없으면 Area(예: 팀 운영, 학습).
- 애매하면 Project 로 시작하고, 지나고 보니 Area 였으면 그때 옮긴다. 프로젝트가 끝나면 Archive 로 이동한다.
- 여러 프로젝트에 걸친 회의록은 비중이 가장 큰 한 곳에 두고 다른 프로젝트 인덱스에서 링크한다.
- 한계: PARA 는 상태를 폴더 위치로 표현하므로 상태가 바뀔 때마다 파일을 옮겨야 하고 경로에 묶인 링크가 깨지기 쉽다(Obsidian 에서는 동명 파일 모호성 때문에 풀 경로 위키링크를 쓰게 된다). 또 "끝났다"와 "틀렸다·대체되었다"를 같은 Archive 이동으로밖에 표현하지 못한다.
- 팀 문서 저장소에서는 PARA 를 폴더 대신 속성으로 흡수하는 방식도 쓴다.
