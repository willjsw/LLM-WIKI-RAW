# 개인 지식 볼트 규칙이 무너지는 근본 원인

## Analysis

한 볼트의 운영 실적을 진단해 증상을 근본 원인으로 묶었다.

| 근본 원인 | 드러난 증상 |
|---|---|
| 규칙이 문장으로만 있고 기계 검사가 없다 | type 값이 정의 5종에서 실사용 20종 이상으로, status 가 22종(`in_progress`/`in-progress` 혼재)으로 늘어 집계가 깨짐. 머리말 없는 노트 57건. 가이드가 전제한 플러그인이 없어 템플릿·자동 집계가 동작하지 않음 |
| 지식 승급이 사람의 정기 규율에만 의존 | 영구 노트 0건 |
| 문서에 출처·저자·검증 상태 축이 없다 | 회의록 안에서 결정과 논의 중 의견이 섞임, 같은 회의의 여러 판에 정본 표시 없음, AI 작성 여부 구분 불가 |
| 상태를 폴더 위치에 맡겼다 | 상태가 바뀔 때마다 이동, 경로 의존 링크, "끝남"과 "틀림·대체됨" 구분 불가, Inbox 폴더가 옮겨지자 그 경로에 고정된 정리 스킬이 조용히 아무것도 처리하지 않음 |
| 커밋·푸시가 운영 절차에 묶이지 않았다 | 미커밋 누적, 원격 없음 → 백업·공유 불가 |

**추가 관찰.** 운영 가이드가 실제 환경(설치된 플러그인, 존재하는 스크립트, 프로젝트 목록)과 다르면 규칙 전체의 신뢰가 떨어진다. 경로를 하드코딩한 자동화는 경로가 바뀌어도 에러 없이 멈추므로 알아차리기 어렵다.

**개선 방향.** (1) 타입·상태 허용 값을 한 파일에 정본화하고 값을 일괄 통일, (2) origin 과 타입별 상태로 신뢰 축 추가, (3) 회의록에서 결정을 별도 노트로 분리, (4) 허용 값·필수 필드를 커밋 전이나 정기 스윕에서 기계로 검사, (5) 도구 의존과 가이드를 실제 환경에 맞추기.
