# 통계 필드 이름 짓기와 항목 분리 원칙

## Purpose

통계 테이블 컬럼을 새로 정의하거나 기존 컬럼을 바꿀 때 이름과 항목 단위를 일관되게 정한다.

## Steps

1. 기존 테이블 컬럼의 실제 의미를 먼저 파악한다. 뜻을 확인하기 전에 이름부터 바꾸지 않는다.
2. 이름은 `[대상]-[행위]-[집계 대상]` 순서로 짓는다.
3. 행위는 의미 중심 용어로 바꾼다. 예: talk → answered, abandoned → not_answered, 이름과 실제 의미가 다른 talk_range는 wait 계열로.
4. IB/OB 접두사는 방향 구분이 꼭 필요한 항목에만 붙인다. abandoned, RONA처럼 방향 구분이 의미 없는 항목에는 붙이지 않는다.
5. 항목을 삭제하거나 쪼갤 때는 "그 값을 어떤 원천에서 어떻게 얻는가"를 먼저 확인한다. 나누기 어려우면 버리고, 공수가 들지 않으면 세세하게 나눈다.
6. 평균은 저장하지 않고 합계와 건수를 raw로 둬 사용처가 나눠 쓰게 한다.
7. 기존 한 필드가 새 구조에서 여러 필드의 합이 되는 경우(예: RONA = 재큐잉 + 회수)는 별도 표로 합산 규칙을 남긴다.
8. 채널이 다른 데이터(예: 채팅)는 별도 테이블로 두고 테이블 이름에 채널을 명기한다.
9. 서비스 레벨처럼 바뀌지 않는 인프라 설정값은 하드코딩이나 설정 파일로, 바뀔 수 있는 메타데이터는 테이블로 관리한다.
