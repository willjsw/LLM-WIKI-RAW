# 온톨로지 기반 AX에서 FDE가 메우는 간극

## Analysis

기업 AI 전환(AX)은 기존 조직 체계에 AI를 얹는 것이 아니라 업무 구조를 재구축하는 일이라는 주장이다. 이유는 세 가지 장애에 있다 — 흩어지고 신뢰하기 어려운 데이터, AI가 이해하지 못하는 업무 맥락, 현장에 정착하지 못하는 AI.

각 장애에 대한 처방은 데이터 통합·품질·출처 관리, 온톨로지로 업무 지식 연결, 그리고 현장에 들어가 정착을 돕는 FDE(Forward Deployed Engineer)다. 온톨로지를 만들려면 요구사항 분석, 구조 설계, 온톨로지 검증, 데이터 검증이 선결되어야 하는데, 이 과정에서 고객의 도메인 지식과 개발사의 기술 지식 사이에 간극이 생긴다. FDE의 역할은 이 간극을 메우는 것으로, 업무 구조 설계, 현장 문제 정의, CQ("여기까지는 AI가 답할 수 있어야 한다") 정의가 핵심 산출물이다.

또한 온톨로지를 지식 + 절차 + 동작으로 보고, 당분간은 최하단에 결정론적 워크플로를 강제하고 그 위에서 AI가 진행하는 구조가 유지될 것으로 전망했다. 장기적으로는 시드 온톨로지를 처음에 구축한 뒤 에이전트를 통해 스스로 개선하는 방향(온톨로지 → 스킬 → 메모리 시스템)을 제시했다.

이 관점은 "AI 도입은 기술 도입이 아니라 업무 재설계"라는 다른 컨퍼런스의 결론과 같은 방향이다.
