# Daily 메모를 영구 노트로 승급하는 주간 절차

## Purpose

분류 고민 없이 쌓은 일일 메모(발산)에서 재사용 가치가 있는 것만 골라 self-contained 영구 노트(수렴)로 옮긴다.

## Steps

1. 평소에는 Daily 노트에 분류 결정 없이 시계열로 적는다. 대상: 내가 한 의사결정 발언, 콘솔 에러와 임시 해결, 회의 전후 follow-up, 새로 안 명령어·API, 디버깅 가설과 결과. 회의록 본체와 정식 스펙은 각자 위치에 쓴다.
2. 주 1회(30분) 지난 7일치 Daily 를 순서대로 연다.
3. 항목마다 다음 중 2개 이상 해당하는지 본다: 다른 프로젝트에서 다시 참조할 기술 솔루션 / 동료가 같은 문제를 만나면 시간 절약 / 재사용 가능한 명령어·패턴·스니펫 / 디버깅 근본 원인이 명확해짐 / 비자명한 의사결정 배경 / 6개월 뒤에도 이해 가능한 내용. 일회성 메모, 너무 좁은 맥락, 이미 스펙에 있는 내용은 승급하지 않는다.
4. 해당 라인에 `(승급)` 또는 `(스킵)` 마커를 붙인다.
5. 승급 항목마다 영구 노트를 만들고 머리말에 원본 Daily 링크(`promoted_from`)를 남긴다.
6. raw 메모를 복사하지 말고 6개월 뒤의 자신이 이해하도록 self-contained 로 다시 쓴다.
7. 원본 Daily 라인 옆에 승급 노트 링크를 붙이고 백링크가 양쪽에서 보이는지 확인한다.
8. 한 달에 승급이 0건이면 절차가 돌지 않는 신호로 보고 원인(적재가 막힘, 리뷰 누락)을 찾는다. 사람의 규율에만 맡기면 멈추기 쉬우므로 후보 추출이나 알림을 자동화로 보조한다.
