# 문서 저장소의 AI 활용 방식 비교와 도입 순서

## Analysis

**세 방식 비교**

| 방식 | 장점 | 단점 | 전제 조건 |
|---|---|---|---|
| MCP 직접 조회 | 별도 구축이 없고 항상 최신 | 페이지 단위 호출로 느림, 큰 페이지 잘림, 접근 통제 약함 | 영역별 인덱스 페이지, AI 공개 속성 |
| md 미러 + RAG (정기 export → 프론트매터 포함 md → 벡터 인덱스) | 빠르고 오프라인 가능, 메타데이터 필터 검색, 개인 볼트와 연동 | 동기화 지연, 미러 보관 시 보안 관리 필요 | 프론트매터 표준, 비밀정보 배제 |
| 지식그래프·온톨로지 (엔티티 DB + Relation → 그래프) | 관계 질의(특정 대상에 영향 준 결정과 장애), 영향도 분석 | 구축·유지 비용 최대, 엔티티 표기 규칙 준수 필요 | 엔티티 DB, Relation, type |

**권장 순서(제안)**: 메타데이터 정비 → MCP 직접 조회 + 영역 인덱스 → md 미러 + RAG → 온톨로지. 앞 단계의 산출물(속성, 인덱스 문서, 프론트매터, 엔티티 표기)이 다음 단계의 입력이 되므로 순서를 바꾸면 뒤 단계가 부실한 데이터를 받는다.

**MCP 리소스 운영 원칙**
- 영역별 인덱스 문서(영역 개요, 명령 체계 등)를 진입점 리소스로 제공해 에이전트의 탐색 비용을 줄인다.
- 상태가 표준이고 AI 공개 범위가 제한이 아닌 문서만 노출한다.
- 큰 문서는 고정 헤딩 기준으로 섹션 단위로 쪼개 응답 잘림을 막는다.

**지속 점검**: 분기 1회 대표 질문 10개를 AI 에 질의해 답변 정확도를 점검하고, 틀린 답의 원인 문서를 수정한다.
