# WebSocket·STOMP 단계별 오류 전달과 Close 코드

## Definition

STOMP over WebSocket 의 오류는 HTTP 핸드셰이크 상태 코드, STOMP ERROR 프레임(뒤이어 close 1002), 연결을 유지한 MESSAGE 응답의 세 단계로 나뉜다. STOMP 1.2 에는 숫자 오류 코드가 없어 ERROR 의 `message` 헤더와 본문으로 원인을 전한다.

## Evidence

- 핸드셰이크(RFC 6455 §4): 101 성공, 403 Origin 거부, 404 경로 없음(SockJS 미사용이면 SockJS 경로도 404), 400 `Upgrade`/`Connection`/`Sec-WebSocket-*` 헤더 누락(프록시가 헤더를 버린 경우 포함). 브라우저 JS 에는 핸드셰이크 실패가 close 1006 으로만 보인다.
- Close 코드(RFC 6455 §7.4.1): 1000 정상, 1001 서버 종료·페이지 이탈, 1002 프로토콜 오류, 1003 받을 수 없는 데이터, 1006 close frame 없이 끊김(예약 코드로 실제 전송되지 않고 브라우저가 붙인다), 1008 정책 위반, 1009 크기 초과, 1011 서버 내부 오류.
- Spring 은 STOMP ERROR 송신 직후 `StompSubProtocolHandler` 가 무조건 연결을 1002 로 닫는다.
- Origin 을 HTTP 업그레이드에서 막으면 403 으로 끝나 ERROR 프레임을 보낼 수 없고, 클라이언트 SDK 는 네트워크 오류와 구분하지 못해 재연결 상한까지 시도한다. ERROR 로 알리려면 CONNECT 단계에서 따로 검사해야 한다.
- 커스텀 ERROR 는 `message` 헤더에 코드, `content-type: application/json`, 본문 `{resultCode, resultMessage}` 로 보낼 수 있다. 1009·1011 조건은 Spring 기본 동작 기준이며 실측하지 않았다.
