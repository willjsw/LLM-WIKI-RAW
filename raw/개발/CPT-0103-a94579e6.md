# 비동기 콜백 user data 는 호출 함수보다 오래 살아야 한다

## Definition

비동기 API 에 넘기는 콜백 user data(컨텍스트 포인터)는 콜백이 실제로 불리는 시점까지 유효해야 하므로, 등록한 함수의 스택 지역변수나 곧 반납·재사용될 슬롯 주소를 넘기면 안 되고 힙에 할당해 콜백이 끝날 때 해제해야 한다.

## Evidence

- 재생 완료 콜백의 user data 를 스택 지역변수로 넘겨, 함수 반환 후 콜백이 쓰레기 값을 읽을 수 있었다(반복 재생 여부, 알림 판단 등이 오동작).
- user data 로 작업 컨텍스트 슬롯 주소를 넘겼는데 워커가 핸들러 반환 직후 컨텍스트를 삭제해, 슬롯이 재사용되면 DTMF 숫자가 다른 통화 당사자에게 보고될 수 있었다.
- 비슷한 유형으로, 객체가 완료 시점에 `delete this` 하는데 호출자 핸들이 남아 있는 경우와 `new[]` 로 할당하고 `delete` 로 해제하는 경우(정의되지 않은 동작)도 같은 분석에서 나왔다.
- 수정 방향: user data 를 힙에 두고 소유권을 콜백으로 넘겨 콜백 마지막에 해제한다. 콜백이 공유 컨텍스트를 직접 참조하지 않게 필요한 값을 복사해 둔다.
