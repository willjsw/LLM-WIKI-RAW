# ClassLoader 위임 모델과 Namespace

## Definition

JVM의 ClassLoader는 Bootstrap → Extension → System → User-Defined 계층을 이루고, 클래스를 찾을 때 캐시 → 부모 → 자신 순으로 부모에게 먼저 위임한다. 각 ClassLoader는 자신이 로드한 클래스의 Namespace를 따로 가지며, JVM 안에서 같은 클래스는 ClassLoader·패키지·클래스명이 모두 같아야 한다.

## Evidence

- `loadClass()`: 이미 로드했으면 반환 → 아니면 부모에 위임 → 부모가 못 찾으면 `findClass()`로 직접 탐색
- 하위 로더의 클래스는 상위 로더에서 보이지 않는다. 그래서 사용자 클래스를 bootstrap·extension 경로에 두면 안 된다
- ClassLoader가 다르면 같은 클래스도 중복 로딩된다. 이것이 WAS의 애플리케이션별 라이브러리 격리와 Hot Deploy(새 로더로 새 버전 로딩)의 근간이다
- 반대로 ClassLoader를 계속 새로 만들면 같은 클래스가 무한히 적재되어 Metaspace 누수가 된다
- ClassNotFound 문제는 위임 순서(Bootstrap부터 탐색)를 따라가며 어느 로더의 경로에 클래스가 있어야 하는지로 추적한다
- `-Xbootclasspath/p`로 앞에 붙인 jar는 표준 라이브러리 클래스를 대체할 수 있다(APM 에이전트가 쓰는 방식)
