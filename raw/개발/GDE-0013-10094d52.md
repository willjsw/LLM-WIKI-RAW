# Heap Dump 기반 메모리 이슈 분석 4단계

## Purpose

Heap Dump에서 메모리를 가장 많이 잡고 있는 객체와, 그것을 놓아주지 않는 보유자를 찾아 누수 원인을 규명한다.

## Steps

1. Overview: 전체 Heap 크기, 객체·클래스·클래스로더 수, 클래스 히스토그램으로 규모를 파악한다
2. Find Big Object: Dominator Tree나 Biggest Objects by Retained Size로 큰 객체를 특정한다(강의 기준 이 단계로 약 80%가 해결된다)
3. Inspect Content: Dominator Tree를 펼쳐 retained set과 outbound reference, 필드 값을 확인한다. 클래스별 인스턴스 수와 합계 크기도 본다
4. Identify Holders: inbound reference와 Path to GC Roots(Merge Shortest Paths)로 누가 붙들고 있는지 규명한다
5. 필요하면 ClassLoader별 로딩 현황(Metaspace 누수), 덤프에 포함된 스레드 Call Stack, OQL, 두 시점 덤프 비교를 추가로 쓴다
6. 클래스 이름만 보고 원인을 추정할 수 있도록 개발 당사자와 함께 분석한다
