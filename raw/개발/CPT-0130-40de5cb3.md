# ServiceLoader SPI 팩토리 설계 시 주의점

## Definition

Java ServiceLoader 로 구현을 찾는 SPI 팩토리는 이름을 돌려주는 메서드에서 선택적 라이브러리 클래스를 참조하면 안 되고, 이름 중복과 초기화 실패는 기동 시점에 바로 예외로 멈춰야 한다.

## Evidence

- `name()` 이 벤더 jar 의 클래스를 정적 참조하면 그 jar 가 없는 환경에서 ServiceLoader 열거 자체가 실패해, 쓰지도 않는 provider 때문에 다른 provider 까지 못 찾는다. 대상 클래스 로드는 `create()` 안에서 처음 일어나게 한다.
- 같은 이름의 어댑터가 classpath 에 둘 있으면 순회 순서에 따라 다른 구현이 골라지고 기동은 정상처럼 보이면서 동작만 달라진다. 조용히 고르지 말고 예외로 멈춘다.
- `ServiceConfigurationError` 는 자기 계층의 예외로 변환한다.
- 키 부재, 형식 오류, 라이선스 문제 같은 초기화 실패는 첫 사용까지 미루지 않고 기동에서 터뜨린다.
- 벤더 어댑터를 리플렉션으로 구현하면 라이선스 jar 를 저장소에 넣지 않고도 빌드·검증할 수 있다.
