# SIP 시그널링과 RTP 미디어의 분리

## Definition

SIP(RFC 3261)는 세션을 만들고·바꾸고·끝내는 신호만 담당하고, 실제 음성·영상은 RTP(RFC 3550)가 별도 경로로 나른다. 둘 사이의 협상 결과(미디어를 받을 IP, 포트, 코덱)는 SIP 메시지 바디의 SDP(RFC 4566)로 전달된다.

## Evidence

- 역할을 나누면 서버는 신호만 중계하고 음성은 단말끼리 직통으로 흘려 서버 부하와 지연을 줄일 수 있다.
- 미디어 직통은 지연이 가장 작지만 양쪽이 NAT 뒤면 실패하고 녹취가 안 된다. 미디어 중계(미디어 서버 경유)는 NAT 통과와 녹취·전환이 가능하지만 서버 대역폭·CPU 와 지연이 늘어난다. SDP `c=` 라인 IP 가 상대 단말이면 직통, 서버면 중계다.
- SDP 에서 실무로 볼 줄은 `c=`(미디어를 받을 IP)와 `m=`(포트, 코덱 목록) 두 줄이다. Offer/Answer(RFC 3264)에서 Answer 는 Offer 의 코덱 중에서만 고르고 `m=` 라인 개수·순서를 유지하며 쓰지 않는 미디어는 포트 0 으로 거절한다.
- 서버 종류: Registrar(위치 등록), Proxy(중계·forking), Redirect(3xx 로 안내), B2BUA(양쪽을 별개 세션으로 끊어 붙여 통화 전체를 통제), Location Service(바인딩 저장소). 녹취·전환·과금(CDR)이 필요하면 순수 프록시로는 통화를 조작할 수 없어 B2BUA 로 동작해야 한다.
- 기본 포트는 5060(UDP/TCP), 5061(TLS)이다. SIP 는 HTTP 처럼 텍스트 요청/응답이지만 UDP 가 기본이고 양쪽이 모두 요청을 보내며 통화라는 장기 상태를 유지한다.
