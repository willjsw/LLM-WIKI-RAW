# 작업 트리 해시로 검증 결과 캐시하기

## Definition

검증이 통과한 시점의 작업 트리 내용(추적·미추적 파일 포함)을 git 트리 해시로 키를 만들어 기록하고, 다음 실행에서 키가 같으면 검증을 건너뛰는 방식이다. 커밋 직후 post-commit 처럼 방금 검증한 트리를 다시 검증하는 중복을 규칙 변경 없이 없앤다.

## Evidence

- 키 계산: `tmp=$(mktemp); GIT_INDEX_FILE=$tmp git add -A && key=$(GIT_INDEX_FILE=$tmp git write-tree)`. 임시 인덱스를 써서 실제 인덱스를 건드리지 않는다.
- 커밋 직후 `HEAD^{tree}` 는 커밋 전에 검증한 작업 트리와 같으므로 post-commit 검증이 즉시 끝난다. 코드가 바뀌지 않은 리뷰 재시도·수동 재실행도 함께 빨라진다.
- 기록은 worktree 들이 공유하도록 `<git-common-dir>` 아래(예: `harness-verify/pass-<key>`)에 둔다.
- 주의: 결과가 트리 밖(도구 버전, 런타임 버전, 환경 변수)에 좌우되면 캐시가 틀릴 수 있으므로 키에 도구·python·node 버전을 섞는다. 캐시 무시 옵션을 둔다.
- CI 는 새 클론이라 캐시가 없으므로 머지 전 검증은 그대로 돈다. 사람이 검증 없이 커밋하면 post-commit 이 지금처럼 전체를 돈다.
- 확장: 단계마다 통과 트리 해시를 남기고, 그 뒤 바뀐 파일이 그 단계의 대상 경로에 걸리지 않으면 건너뛴다. 예시 이슈 추정으로 검증 시간 72분 → 36분(캐시만).
