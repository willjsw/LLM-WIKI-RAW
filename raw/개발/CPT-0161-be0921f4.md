# SIP 트랜잭션 타이머와 32초 실패의 정체

## Definition

UDP 위의 SIP 는 재전송을 프로토콜이 직접 하며, RTT 추정치 T1(기본 500ms)을 기준으로 지수 백오프한다. 트랜잭션 타임아웃 Timer B(INVITE)와 F(non-INVITE)가 64×T1 = 32초라서 "SIP 가 32초 만에 실패한다"는 현상은 거의 항상 이 타이머다.

## Evidence

- 상수: T1 = 500ms, T2 = 4초(재전송 간격 상한), T4 = 5초(메시지가 망에 남는 최대 시간).
- INVITE 재전송(UDP, 응답 없음): 0, 0.5, 1.5, 3.5, 7.5, 15.5, 31.5초에 보내고 32초에 Timer B 만료 → 408 Request Timeout.
- non-INVITE 재전송(Timer E)은 T2(4초)에서 증가를 멈추고 4초 간격으로 반복한다. INVITE 는 사람이 받는 데 시간이 걸리므로 상한 없이 두 배가 된다.
- `100 Trying` 의 역할은 "받았다"를 빨리 알려 상대의 재전송을 멈추게 하는 것뿐이며 hop-by-hop(다음 홉까지만)이다.
- UAS 는 2xx 를 Timer G 로 재전송하고 Timer H(32초) 동안 ACK 를 기다린다. ACK 가 유실되면 200 OK 가 반복되다 약 32초 뒤 세션을 포기해 "받았는데 30초쯤 뒤 저절로 끊긴다"는 증상이 된다.
- TCP 는 커널이 재전송하므로 흡수 타이머(D/I/J/K)가 0 이 되어 트랜잭션이 즉시 정리된다. "UDP 는 32초, TCP 는 즉시"로 기억한다.
- 프록시는 응답 없는 forking 분기를 Timer C(3분 초과 권장)로 정리한다.
