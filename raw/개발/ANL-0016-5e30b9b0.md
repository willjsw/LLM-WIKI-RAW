# 실패 배치 재시도 시 신규 실행 생성과 기존 행 갱신 비교

## Analysis

실패(FAILED), 타임아웃(TIMEOUT), 누락(OMISSION)된 배치를 재시도할 때 실행 이력을 다루는 방식은 두 가지다.

**A. 실패 행은 그대로 두고 새 root 실행을 트리거**
- 재시도마다 새 실행 로그가 생긴다.
- 실패한 행이 다시 연쇄 재시도되지 않도록 RETRIED 같은 상태 코드가 필요하고, 원 실행과 재시도 실행을 잇는 추적 필드도 필요하다.
- 정규 스케줄과 같은 Job 이름으로 동시에 실행될 수 있어 충돌 제어가 필요하다.
- 체인과 작업 그룹 단위 실행을 그대로 활용할 수 있다.

**B. 기존 행의 상태만 갱신**
- 로그가 늘지 않고 한 행에서 최종 상태를 볼 수 있다.
- 실행할 때마다 새 행을 insert하는 작업 유형과 전제가 충돌하고, 체인을 쓰기 어렵다.
- 외부 스크립트를 개별 실행 단위로 쪼개고 병렬 실행을 스케줄러가 맡아야 한다.

운영 판단: 집계 작업들은 서로 의존하므로 재실행 단위를 개별 Job이 아니라 Job Group으로 잡는 편이 일관적이다. 어떤 방식이든 재실행이 같은 집계 구간을 중복 적재하지 않도록 집계 쿼리 자체가 멱등이어야 한다.
