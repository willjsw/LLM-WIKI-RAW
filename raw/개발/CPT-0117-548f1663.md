# WebSocket 연결 수립과 프레임 특성

## Definition

WebSocket 은 HTTP 요청 한 번으로 연결을 업그레이드한 뒤 같은 TCP 연결 위에서 양방향(전이중) 프레임을 주고받는 프로토콜이다. 통로만 제공하고 메시지 의미는 정하지 않는다.

## Evidence

- 핸드셰이크: `Upgrade: websocket`, `Connection: Upgrade`, `Sec-WebSocket-Key`, `Sec-WebSocket-Version: 13` 요청에 서버가 `101 Switching Protocols` 와 `Sec-WebSocket-Accept` 로 답한다. `Sec-WebSocket-Protocol` 로 위에 얹을 서브프로토콜(예: STOMP 1.2)을 합의한다.
- 서버가 요청 없이 먼저 보낼 수 있다는 점이 HTTP 폴링과의 핵심 차이다.
- `ws://` 평문, `wss://` TLS. 운영은 wss 만 쓴다.
- opcode: 텍스트, 바이너리, ping/pong(생존 확인), close.
- 클라이언트→서버 프레임 마스킹은 프록시 캐시 오염 방지용이며 암호화가 아니다.
- 종료 코드: 1000 정상, 1001 떠남(탭 닫힘 등), 1006 비정상 끊김(실제로 전송되지 않고 끊김을 나타내는 값).
