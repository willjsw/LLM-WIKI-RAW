# PostgreSQL SECURITY DEFINER로 테이블 소유권 변경 없이 DDL 위임

## Definition

`SECURITY DEFINER`로 선언한 함수/프로시저는 호출한 계정이 아니라 객체 소유자의 권한으로 실행된다. 함수 소유자를 대상 테이블 소유 계정으로 두면 호출 계정에 DDL 권한을 주지 않고도 파티션 생성 같은 작업을 맡길 수 있다.

## Evidence

- 파티션 관리 프로시저가 권한 오류로 실패했다. 테이블 소유권을 바꾸는 대신 `ALTER FUNCTION/PROCEDURE ... OWNER TO <부모 테이블 소유 계정>`으로 함수 소유자만 바꿔 해결했다.
- 함수/프로시저는 생성 시 PUBLIC에 EXECUTE가 기본 부여된다. `REVOKE EXECUTE ... FROM PUBLIC` 후 실제 호출 계정에만 `GRANT EXECUTE`한다.
- 호출 계정에는 진입점 프로시저 EXECUTE와 스키마 USAGE만 있으면 된다. 부모 테이블 DDL 권한이나 스키마 CREATE 권한은 필요 없다.
- 테스트 환경에서 파티션 생성, 소유자·권한 승계, 작업 로그 적재, 스키마 간 위임 호출이 정상 동작했다.
