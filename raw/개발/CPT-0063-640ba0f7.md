# JVM Runtime Data Area와 공유 범위

## Definition

Runtime Data Area는 프로세스로서의 JVM이 프로그램 수행을 위해 OS로부터 할당받은 메모리 영역이다. Method Area와 Heap은 모든 스레드가 공유하고, PC Register·JVM Stacks·Native Method Stacks는 스레드마다 만들어진다.

## Evidence

- JVM 실행 흐름: Class Loader가 클래스를 적재 → Execution Engine이 해석 → Runtime Data Area에 배치되어 수행 → 그 과정에서 스레드 동기화와 GC 수행
- 공유된다는 것은 락 병목이 생길 수 있다는 뜻이다. Method Area와 Heap의 할당·회수는 락 경합과 Stop-The-World의 진원지가 되고, 스레드별 영역은 경합이 없다
- Hotspot에서 Java 스레드와 OS 네이티브 스레드는 1:1로 매핑되므로 스레드 수 증가가 곧 커널 스레드와 컨텍스트 스위칭 비용 증가다(Virtual Thread는 이 전제를 바꾼다)
- JVM Stack은 메서드 호출마다 Stack Frame(Local Variable Section, Operand Stack, Frame Data)을 push하며, 프레임 크기는 컴파일 시점에 정해진다
- 스택이 허용 크기를 넘으면 StackOverflowError, 스택 확장·새 스레드 스택 생성에 메모리가 부족하면 OutOfMemoryError가 난다
