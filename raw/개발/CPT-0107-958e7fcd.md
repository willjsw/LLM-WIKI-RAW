# Spring AI MCP 서버는 스펙 객체 빈을 모아 등록한다

## Definition

Spring AI 의 MCP 서버 자동 설정은 `List<SyncToolSpecification>`, `List<SyncResourceSpecification>`, `List<SyncResourceTemplateSpecification>`, `List<SyncPromptSpecification>`, `List<SyncCompletionSpecification>` 타입 빈을 ObjectProvider 로 모아 서버에 등록하므로, 해당 타입의 빈을 만들면 등록이 끝난다.

## Evidence

- SDK 서버가 아는 것은 '메타데이터 + 처리 함수' 쌍인 스펙 객체뿐이다.
- Tool 은 `@Tool` 메서드를 `MethodToolCallbackProvider` 빈으로 넘기면 Spring AI 가 메서드 시그니처로 입력 JSON 스키마를 만들고 SyncToolSpecification 으로 감싼다.
- Resource·Prompt 는 메타데이터가 단순해 `SyncResourceSpecification(Resource, 읽기 함수)`, `SyncPromptSpecification(Prompt, 생성 함수)` 를 직접 만들어도 짧다. 처리 함수는 첫 인자로 `McpSyncServerExchange` 를 받는다.
- tool 안에서 현재 MCP 세션에 접근하려면 메서드에 `ToolContext` 파라미터를 선언하고 `McpToolUtils.getMcpExchange(toolContext)` 로 exchange 를 꺼낸다. 진행률 알림, 실행 중 사용자 확인(elicitation), 로깅 알림에 쓴다.
- HTTP 요청 정보를 담는 transport context 의 기본 추출기는 빈 값을 돌려주므로, 쓰려면 트랜스포트 프로바이더 빈을 직접 정의해야 한다.
- 관련 설정 `spring.ai.mcp.server.*`: instructions, capabilities.tool/resource/prompt/completion, 목록 변경 알림, annotation-scanner.enabled(기본 true).
