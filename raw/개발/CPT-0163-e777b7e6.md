# SIP 라우팅의 Via 와 Record-Route

## Definition

Via 는 응답이 되돌아올 경로를, Record-Route/Route 는 초기 요청 이후의 요청이 반드시 거칠 경로를 정한다. Contact 는 다음 요청을 직접 보낼 주소다. 프록시가 Record-Route 를 남기지 않으면 이후 BYE·re-INVITE 가 프록시를 건너뛴다.

## Evidence

- Via 규칙: 요청을 전달할 때 자기 Via 를 맨 위에 추가하고, 응답을 받으면 맨 위 Via 가 자기 것이 아니면 폐기하며, 응답을 전달할 때는 맨 위 Via 를 제거하고 그 아래가 가리키는 곳으로 보낸다.
- Record-Route: 초기 INVITE 와 그 응답에 프록시가 추가하고, 양쪽 UA 가 Route Set 으로 저장해 이후 요청에 `Route` 로 넣는다.
- Record-Route(또는 B2BUA)가 없으면 PBX 가 통화 종료를 인지하지 못해 CDR 이 남지 않고 통화 상태가 좀비로 남는다. 과금·녹취·통계가 필요한 시스템에서는 필수다.
- loose routing(`;lr`)은 Request-URI 를 최종 목적지로 두고 경유지는 Route 로 표현한다. 현행 구현은 전부 이 방식이다.
- 목적지 결정(RFC 3263): Route 맨 위가 있으면 그것, 없으면 Request-URI. 도메인이면 NAPTR → SRV(priority 낮을수록 우선, 같으면 weight 가중 랜덤) → A/AAAA 순으로 조회하며 여기서 failover 와 부하 분산이 일어난다.
- Forking: parallel 은 여러 Contact 에 동시에 보내고 먼저 200 OK 를 준 쪽이 이기며 나머지는 CANCEL 한다. 2xx 는 즉시 전달하고 6xx 를 받으면 나머지 분기를 즉시 CANCEL 한다. Stateless 프록시는 forking 과 CDR 이 불가하다.
