# 조건변수 신호 유실 - 상태는 mutex 안에서 바꾸고 signal 한다

## Definition

워커에게 일을 넘길 때 공유 상태(처리할 함수 포인터, 요청 플래그)를 mutex 없이 바꾸고 `cond_signal` 을 보내면, 워커가 아직 `cond_wait` 에 들어가기 전이면 신호가 유실돼 요청이 영원히 처리되지 않는다(lost wakeup).

## Evidence

- 실제 분석 사례에서 이 패턴 때문에 요청이 처리되지 않고 상위 계층의 타임아웃으로만 드러났다.
- 올바른 형태: 보내는 쪽은 mutex 를 잡고 상태를 바꾼 뒤 signal 한다. 받는 쪽은 mutex 를 잡고 `while (조건 불충족) cond_wait(...)` 로 조건을 다시 확인한다. 조건 변수는 '상태'가 아니라 '깨우기'만 전달하므로 상태 확인 없이 wait 하면 안 된다.
- 같은 분석에서 감시 루틴이 작업 중(BUSY) 여부를 보지 않고 오래된 슬롯을 지워 이중 반납되는 결함도 나왔다. 상태 확인과 상태 변경은 같은 잠금 안에서 해야 한다.
