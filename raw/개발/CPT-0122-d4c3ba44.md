# PostgreSQL 선언적 파티셔닝 제약

## Definition

PostgreSQL 선언적 파티션 테이블은 파티션 키가 모든 PRIMARY KEY·UNIQUE 제약에 포함되어야 하고, 파티션 키는 NULL 이 없어야 행을 배정할 수 있다. 기존 일반 테이블에는 ALTER 로 `PARTITION BY` 를 붙일 수 없다.

## Evidence

- PK/UNIQUE 에 파티션 키가 없으면 제약 생성이 실패한다. 단일 서로게이트 키 PK 는 `(id, <파티션키>)` 복합 PK 가 되며, 이를 참조하는 FK 와 애플리케이션 조회 코드에 영향이 있다.
- NULL 허용 컬럼을 키로 쓰려면 `DEFAULT now() NOT NULL` 처럼 승격하고, 기존 NULL 값은 이관 시 `COALESCE` 로 채운다.
- `ALTER TABLE ONLY ... ADD CONSTRAINT` 의 ONLY 는 자식 파티션에 제약을 전파하지 않으므로 파티션 테이블에서는 ONLY 없이 쓴다.
- 부모 테이블에 만든 인덱스는 각 파티션에 자동 전파된다.
- 해당 범위의 파티션이 없으면 INSERT 가 `no partition of relation` 오류로 실패한다.
- 파티션 생성(`CREATE TABLE ... PARTITION OF`)과 분리(`DETACH PARTITION`)는 부모 테이블 소유자만 할 수 있다.
