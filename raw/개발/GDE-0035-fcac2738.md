# 이슈별 git worktree 병렬 작업 안전 수칙

## Purpose

한 리포에서 이슈 여러 개를 동시에 진행할 때(특히 AI 에이전트 세션 여러 개) 작업 트리를 이슈마다 나누고, 한 작업 트리에서는 보이지 않던 병렬 결함을 미리 막는다.

## Steps

1. "내가 만들지 않은 미커밋 변경이 없어야 착수" 조건은 풀지 말고 이슈마다 `git worktree` 를 따로 만든다. 브랜치·커밋·원격은 공유되고 체크아웃과 인덱스는 트리마다 따로다.
2. worktree 는 원격 통합 브랜치를 fetch 한 뒤 분리된 HEAD(`git worktree add --detach <경로> origin/<base>`)로 만들고, 그 안에서 기능 브랜치를 새로 판다. 위치는 리포 밖에 둔다. git 이 무시하는 로컬 파일만 필요하면 복사한다.
3. 기존 worktree 를 다시 열 때는 git 공통 디렉터리가 같은지 확인하고, 미커밋 변경이 있으면 멈춘다.
4. 작업이 끝나면 미커밋 변경이나 미push 커밋(`git rev-list --count HEAD --not --remotes` ≥ 1)이 있을 때 남기고 깨끗할 때만 지운다. git 이 답하지 못하면 남기는 쪽으로 판단한다.
5. 임시 리포를 만드는 테스트는 리포 지역 환경 변수를 비워 격리한다.
6. 보호 브랜치 가드는 세션 작업 트리가 아니라 명령이 가리키는 트리(`cd <경로> &&`, `git -C <경로>`)의 브랜치로 판정한다. 풀 수 없는 경로(변수·명령 치환)는 기존 기준을 유지한다. 가드는 미탐을 허용하고 오탐을 피한다.
7. 반복 지적 이력 같은 리포 공용 상태는 `git rev-parse --git-common-dir` 아래에 둔다.
8. 병렬 브랜치가 "다음 번호"를 각자 고르는 테스트 ID 는 머지해도 텍스트 충돌이 나지 않으므로, 테스트 파일이 스스로 중복 번호를 검사해 실패하게 한다. 겹치면 나중에 머지되는 쪽이 번호를 바꾼다.
9. 같은 이름의 설치·등록이 기기 상태를 덮지 않게 같은 이름·다른 경로 등록을 거부하고 `flock` 으로 판정과 등록 사이 경합을 막는다.
10. 같은 파일 끝에 블록을 더하는 병렬 브랜치는 첫 push 전에 rebase 한다. push 뒤 rebase 는 force push 가 필요해 사람이 해야 한다.
11. 에이전트 지시문에 "막힌 명령을 스크립트 파일로 옮겨 실행하는 것도 우회"임을 명시한다.
12. 격리 환경(임시 원격+클론)에서 여러 이슈를 동시에 반복 실행해 실패·경합이 없는지 확인한다.
