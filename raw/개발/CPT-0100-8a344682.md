# 이력형 마스터 테이블에서 키별 대표 행 하나 고르기

## Definition

같은 업무 키의 행이 수정·삭제 이력과 함께 여러 개 쌓이는 테이블에서, `row_number() OVER (PARTITION BY 키 ORDER BY 우선순위)` 로 순번을 매기고 `rn = 1` 만 남겨 키별 대표 행 하나를 고르는 SQL 패턴이다.

## Evidence

- 정렬 1순위를 '삭제되지 않은 행'(`CASE WHEN delete_yn = 'N' THEN 0 ELSE 1 END`), 2순위를 최종 변경 시각(`COALESCE(update_datetime, register_datetime) DESC`)으로 두면 살아 있는 최신 행이 우선이고, 모두 삭제됐으면 마지막 삭제 행이 남는다.
- 수정 시각이 NULL 인 행(한 번도 수정 안 됨)은 COALESCE 로 등록 시각을 쓴다.
- 테넌트가 있으면 PARTITION BY 에 테넌트 키를 넣어야 테넌트 간 ID 충돌을 피한다.
- PostgreSQL 에서는 `SELECT DISTINCT ON (키) ... ORDER BY 키, 우선순위...` 로 더 짧게 쓸 수 있다. 다른 DB 로 옮길 가능성이 있으면 row_number 방식이 이식성이 좋다.
- 대표 행을 고른 뒤 코드 테이블을 LEFT JOIN 해 키를 표시 값(예: 내선 번호)으로 바꿔 뷰로 내보낸다.
