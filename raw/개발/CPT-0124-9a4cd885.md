# 랜덤 암호화와 결정론 암호화의 선택 기준

## Definition

랜덤 암호화는 같은 평문도 매번 다른 암호문을 만들어 안전하지만 암호화된 상태로 동등 비교(`WHERE col = ?`)를 할 수 없다. 결정론 암호화는 같은 키·평문이면 항상 같은 암호문을 만들어 인덱스 조회가 되지만, 같은 값이 같은 암호문으로 보여 빈도와 동일성이 노출된다.

## Evidence

- 랜덤: 메모·주소처럼 검색하지 않는 필드와 설정 비밀에 쓴다.
- 결정론: 전화번호처럼 동등 검색이 필요한 필드에만 쓴다. 성별·등급처럼 값 공간이 좁은 항목에는 쓰지 않는다(암호문 빈도만으로 값이 드러난다).
- 모드를 기본값 없는 필수 인자로 받는 API 가 안전하다. 잘못된 모드는 예외도 로그도 없이 검색만 깨뜨리기 때문이다.
- 구현이 지원하지 않는 모드를 다른 모드로 몰래 대체하지 말고 예외를 던지며, 기동 시점에 지원 모드를 대조해 운영 중 첫 쓰기에서 터지지 않게 한다.
- 복호화는 모드를 받지 않고 암호문 헤더로 판별하게 하면 호출부 실수가 줄어든다.
