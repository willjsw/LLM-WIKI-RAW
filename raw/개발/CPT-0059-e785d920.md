# 에이전트 정책의 4레이어 — 권고와 강제의 구분

## Definition

에이전트용 조직 정책은 관례(`CLAUDE.md`), 규칙(skills), 리뷰 기준(`REVIEW.md`), 강제(hooks)의 네 레이어 파일로 코드화한다. 앞의 셋은 에이전트가 읽고 따르는 권고라 확률적으로 어긋날 수 있고, hooks만 결정론적으로 실행을 차단하므로 어겨서는 안 되는 규칙은 반드시 hooks로 내린다.

## Evidence

| 파일 | 성격 | 담는 것 | 위반 시 |
|---|---|---|---|
| CLAUDE.md | 지식 | 관례, 빌드·테스트 명령, 아키텍처, 자주 하는 실수 | 어긋난 행동(권고) |
| Skills | 규칙 | 보안 표준, API 규약, 컴플라이언스 | 스펙 작성 시 플래그(권고) |
| REVIEW.md | 판정 기준 | 리뷰 항목, 심각도 | 리뷰 지적(권고) |
| Hooks | 강제 | 보호 경로 편집 차단, 포맷 강제, 배포 승인 게이트 | 실행 차단(강제) |

- 에이전트는 세션마다 기억을 잃으므로 정책을 세션 시작마다 읽는 파일로 둔다. 파일이면 diff·리뷰·롤백이 가능하다
- 규제 환경 관리형 설정 예: 시크릿 읽기·임의 웹 요청 거부, 빌드·테스트·린트 명령만 허용, OS 수준 샌드박스와 도메인 허용목록, 관리형 hooks만 실행, 에이전트 환경에서 시크릿 제거
