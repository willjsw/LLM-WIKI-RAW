# 정본 DB write-through와 Redis 작업본 멱등 가드

## Definition

상태와 메시지는 발생 즉시 RDB 정본에 기록한 뒤 Redis 작업본을 갱신(write-through)하고, Redis 는 유실되면 DB 에서 재구성할 수 있는 캐시·전송 파이프로만 쓴다. 중복 수신은 Redis 멱등 키를 주 가드로, DB UNIQUE 제약을 백스톱으로 막는다.

## Evidence

- write-back(나중에 몰아 쓰기)은 금지한다. 순서 커서와 재접속 보완의 기준은 DB 다.
- 멱등 키 예: `dedup:{세션}:{clientMessageId}` → 서버 발급 messageId, TTL 24h.
- 식별자는 하나, 발급자는 하나: 시간순 정렬 가능한 ID(ULID·UUIDv7)가 식별·정렬·커서를 겸하고 한 서비스만 발급한다. 발신 측 `clientMessageId` 는 멱등 전용이다.
- Redis Stream 은 홉 간 전달용이며 소비 후 MAXLEN 으로 트림하므로 영속 저장소가 아니다. typing·presence 같은 휘발 정보는 Pub/Sub 으로만 다룬다.
- 인스턴스 메모리에 세션 상태를 가두지 않아야 다중 인스턴스 수평 확장이 된다.
- 자원 원장(예: 상담원 처리 한도)은 한 서비스에만 두고 사본을 만들지 않는다.
