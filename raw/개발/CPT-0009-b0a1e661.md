# 콜 단위 키 해시 샤딩으로 같은 콜 이벤트를 한 워커에 모으기

## Definition

같은 콜에 속한 이벤트를 하나의 워커 스레드에서 처리하도록 콜 식별자 해시로 샤드를 고르는 방식이다. 샤드 안에서는 락 없이 상태를 갱신할 수 있지만, 라우팅 키가 이벤트마다 일정해야 한다.

## Evidence

- 예: `hash(originalUcid ?: ucid) % max(4, CPU/2)`. 원콜 ID가 있으면 그것을, 없으면 개별 콜 ID를 키로 쓴다.
- 상담사 상태 이벤트는 상담사 키, 큐 이벤트는 콜 ID처럼 엔티티 성격에 맞는 키로 별도 샤드를 둔다.
- 샤드 워커는 버퍼(예: 300건 또는 100ms)를 flush할 때 상태 처리를 먼저 하고 raw 영속은 비동기로 넘긴다. 이 순서면 raw 저장이 재시도 후에도 실패할 때 "상태는 있는데 원본이 없는" 상황이 생긴다.
- 함정: 같은 콜인데 원콜 ID 필드가 어떤 이벤트에는 있고 어떤 이벤트에는 없으면 `?:` 폴백 때문에 다른 샤드로 갈 수 있다. 라우팅 키는 모든 이벤트에서 같은 값이 나오는 필드로 고른다.
- 샤드 간에 걸치는 작업(세션 연결 등)은 별도 단일 스레드(linker)로 모으는데, 그 큐가 포화되면 힌트를 드롭해 세션이 잘못 분리될 수 있다.
