# 클래스 로딩 단계 — Loading, Linking, Initialization

## Definition

ClassLoader Work는 파일 형태의 클래스를 런타임 Type으로 만드는 과정으로, Loading(획득·파싱·Class 인스턴스 생성) → Linking(Verification·Preparation·Resolution) → Initialization(`<clinit>` 실행) 순서로 진행된다.

## Evidence

- Verification: 문법·정합성, final 클래스 상속 여부, Constant Pool과 바이트코드 무결성 검사. `-noverify`로 생략하면 기동은 빨라지지만 검증되지 않은 바이트코드가 JVM Crash를 낼 수 있다
- Preparation: static 변수 메모리를 할당하고 기본값(0, null)으로 채운다. 개발자가 지정한 값은 Initialization에서 들어간다
- Resolution: Constant Pool의 symbolic reference를 direct reference로 바꾼다. 모든 벤더가 첫 실제 사용 시점에 하나씩 처리하는 Lazy 방식을 쓴다
- `final static` 상수는 컴파일 시 인라인되어 클래스 로딩을 유발하지 않는다
- Initialization은 첫 Active Use 때 반드시 수행되며 superclass가 먼저 초기화된다
- 여러 스레드가 동시에 초기화하려 하면 한 스레드만 수행하고 끝나면 나머지에 notify한다. Singleton Holder(static inner class) 패턴이 thread-safe한 이유다
