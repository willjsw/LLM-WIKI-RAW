# 정적 링킹과 동적 링킹, 런타임 로딩

## Definition

정적 링킹은 필요한 라이브러리 코드를 미리 실행파일에 넣는 방식이고, 동적 링킹은 실행하려는 시점에 필요한 모듈을 결합하는 방식이다. 동적 링킹은 다시 빌드 시 의존을 기록하는 방식과, 실행 중 `dlopen()`/`dlsym()`으로 직접 열고 심볼을 찾는 런타임 로딩·링킹으로 나뉜다.

## Evidence

- 정적: 실행파일만으로 실행 가능하고 배포가 단순하지만 크기가 크다(실습에서 약 97배). 라이브러리를 갱신하면 다시 빌드해야 한다
- 동적: 실행파일이 작고 라이브러리만 교체하면 되지만 별도 모듈을 함께 배포해야 한다
- 공유 라이브러리는 로드 주소를 미리 알 수 없으므로 `-fPIC`(위치 독립 코드)로 빌드한다
- 빌드 시 `-L`은 링커에게만 알려주는 경로다. 실행 시 동적 로더가 찾는 경로와 별개이므로 `LD_LIBRARY_PATH` 등을 설정해야 한다
- `dlopen()`으로 연 라이브러리는 `ldd` 의존 목록에 나타나지 않는다
- `nm` 심볼 표기: T=TEXT, D=DATA, B=BSS, U=미정의(외부 참조)
- JVM의 클래스 로딩은 런타임 로딩 + 런타임 링킹과 같은 개념이다
