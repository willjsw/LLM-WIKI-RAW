# Spring STOMP 메시지 처리 순서 보존 설정

## Definition

Spring STOMP 의 inbound·outbound 채널은 기본이 스레드 풀이라 같은 연결의 프레임이라도 처리 순서와 MESSAGE 발송 순서가 바뀔 수 있다. 순서가 계약에 들어가면 `setPreserveReceiveOrder(true)`·`setPreservePublishOrder(true)` 를 켜야 한다.

## Evidence

- 예: "구독(2)을 이력 동기화(5)보다 먼저 하므로 빈 구간이 없다", "마지막 발화 응답 뒤에 종료 이벤트" 같은 전제는 기본 설정에서 성립하지 않는다.
- 두 메서드는 spring-websocket·spring-messaging 7.0.9 에서 확인했다.
- 수신 순서 보존을 켜면 인터셉터 예외 처리 방식이 달라지므로 거절 경로를 통합 테스트로 확인해야 한다(관련 관찰 참고).
