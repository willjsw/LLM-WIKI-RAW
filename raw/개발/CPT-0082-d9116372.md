# CMS와 G1 Collector의 동작 특징

## Definition

CMS는 Old 영역을 Initial Mark(STW) → Concurrent Mark → Remark(STW) → Concurrent Sweep 순으로 애플리케이션과 동시에 수집해 정지를 줄이지만 Compaction을 하지 않는다. G1은 Heap을 Region으로 나누고 Garbage가 가장 많은 Region부터 회수하며 Region 단위로 압축한다.

## Evidence

- CMS의 No Compaction: 시간은 절약되지만 연속된 빈 공간이 줄어 FreeList 기반 할당이 필요하고, 빠른 할당 이점과 승격 효율이 떨어진다
- Floating Garbage: Concurrent Mark 도중 새로 생겼다가 Garbage가 된 객체가 다음 GC까지 남아 메모리 요구량이 늘어난다
- CMS는 JDK 9에서 deprecated, JDK 14에서 제거되었다
- G1이라는 이름은 Garbage로만 가득 찬 Region부터 수집한다는 데서 왔다. Live Data가 적고 Garbage가 많은 Region에 최적이다
- 버전별 기본 GC: Java 7·8은 Parallel GC, Java 11은 G1
