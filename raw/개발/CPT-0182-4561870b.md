# SIP Dialog 식별자와 교환기 이중화 시 Dialog 동기화

## Definition

SIP Dialog는 하나의 통화 세션으로, From tag, To tag, Call-ID 세 값의 조합으로 식별한다. 교환기를 이중화할 때 Standby가 진행 중인 통화의 신호를 이어 처리하려면 이 Dialog 정보가 먼저 동기화돼 있어야 한다.

## Evidence

- 교환기의 통화 풀 구조가 Dialog(통화 세션 정보)를 보관한다.
- 절체 상황에서는 Dialog 동기화 이후에야 시그널 처리가 가능하다는 점이 이중화 설계 쟁점이었다. 공유 메모리에 있는 Dialog를 외부 저장소(예: Redis)로 동기화하는 안이 검토됐다(확정 아님).
- 멀티 테넌트 통화에서는 통화 전체에 테넌트 하나를 두지 않고 각 통화 레그(half-call)마다 테넌트 ID를 두고, 레그 값이 없을 때만 통화 단위 값을 쓰는 방어 로직을 넣는 방향이 논의됐다.
