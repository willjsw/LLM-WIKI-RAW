# JWT 액세스 토큰 검증 결과 3상태 분기

## Definition

액세스 토큰 검증 결과를 VALID, EXPIRED, INVALID 세 상태로 나누고 EXPIRED일 때만 리프레시 토큰을 확인해 재발급하는 인증 분기 방식이다. 서명 위조나 형식 오류인 INVALID는 리프레시 토큰을 보지 않고 즉시 차단한다.

## Evidence

- 구현: `parseClaimsJws` 호출을 감싸고 `ExpiredJwtException`만 별도 catch해 EXPIRED로, 그 밖의 예외는 모두 INVALID로 모은다.
- 위조 AT에 유효 RT를 붙여 재발급을 유도하는 경로가 막힌다. 검증 케이스에서 위조 AT + 유효 RT는 401이 기대값이다.
- RT 검증은 만료를 따로 나누지 않는다. 만료된 RT는 재발급 근거가 될 수 없으므로 서명 오류와 같이 처리한다.
- AT와 RT는 서로 다른 서명 키를 쓴다.
- 재발급 시 RT 클레임을 승계하고 `iat`/`exp`만 새로 채운다. 클레임 값이 이미 암호문이고 게이트웨이가 DB를 조회하지 않으면 재암호화할 이유가 없다.
- 유효 AT 요청에는 응답에 새 토큰을 싣지 않는다(불필요한 재발급 방지).
