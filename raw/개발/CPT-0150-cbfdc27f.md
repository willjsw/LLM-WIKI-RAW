# 생성·관리·소유 파일 세 부류로 갱신 경계 나누기

## Definition

설치형 도구가 프로젝트에 까는 파일을 생성(설정에서 만들어짐, 갱신 때 다시 만듦)·관리(도구 소유, 갱신 때 덮음)·소유(프로젝트 소유, 갱신 때 건드리지 않음) 세 부류로 나누는 방식이다. 부류가 곧 갱신 경계이므로 한 파일에 두 부류가 섞이면 안전하게 갱신할 방법이 없다.

## Evidence

- 같은 값이 여러 파일에 산문으로 박혀 있으면 반드시 어긋난다. 한 리포를 전수 조사했을 때 기본 브랜치 이름이 21파일 65줄, 커밋 태그 목록이 6곳에 있었고 그중 셋은 이미 서로 달랐다.
- 값을 한 곳에 두는 것만으로는 부족하다. 그 값을 쓰는 파일이 전부 같은 곳에서 생성되어야 어긋날 수 없다.
- 생성물이 설정과 어긋나면 검사가 커밋을 막는다. 생성 파일을 손으로 고치면 다음 렌더가 덮는다.
- 삭제(uninstall)는 설치 때 기록한 목록으로 도구가 깐 것만 지운다. 소유 파일과 작업 산출물은 남긴다. 훅 설정(`core.hooksPath`)도 함께 해제해야 한다. 사라진 디렉터리를 가리킨 채 남으면 커밋마다 git 이 실패한다.
- 도구 사본을 프로젝트 안에 커밋해 버전을 고정한다. 전역 CLI 를 올려도 따라가지 않게 해야 전역 업그레이드 한 번에 모든 프로젝트의 생성물과 검사가 한꺼번에 깨지지 않는다.
