# JDK 진단 도구의 용도별 선택

## Definition

JDK 진단 도구는 스레드 분석, Heap Dump 생성, Heap Dump 분석에서 강점이 갈린다. 생성은 jcmd·JMC·VisualVM, 분석은 VisualVM·MAT·IBM HeapAnalyzer가 맡고, 기존 jps·jmap·jstack·jinfo의 기능은 jcmd 하나로 대부분 대체된다.

## Evidence

| 기능 | jcmd | 기존 명령 |
|---|---|---|
| 프로세스 목록 | `jcmd` | `jps -lm` |
| Heap Dump | `jcmd <PID> GC.heap_dump` | `jmap -dump` |
| Heap 히스토그램 | `jcmd <PID> GC.class_histogram` | `jmap -histo` |
| Thread Dump | `jcmd <PID> Thread.print` | `jstack` |
| 시스템 속성 | `jcmd <PID> VM.system_properties` | `jinfo -sysprops` |
| VM 플래그 | `jcmd <PID> VM.flags` | `jinfo -flags` |

- jcmd가 더 최신이고 부하가 적어 jmap 대신 권장된다
- `GC.class_histogram`, `GC.heap_dump`는 Impact가 높다
- `jcmd <PID> VM.native_memory summary|baseline|summary.diff`로 네이티브 메모리를 추적한다(NMT 활성화 필요)
- JMC는 운영 환경 사용 시 라이선스가 필요하고, VisualVM은 OpenJDK에 기본 포함되지 않는다
- 원격 모니터링용 JMX를 열 때는 SSL과 인증을 반드시 켠다. 재기동이 불가하면 `jcmd <PID> ManagementAgent.start`로 동적으로 활성화한다
