# System V 공유 메모리의 key 와 shmid

## Definition

System V 공유 메모리는 프로세스 영역 밖의 OS 메모리를 여러 프로세스가 attach 해 함께 쓰는 IPC 방식이다. 애플리케이션은 key 로 세그먼트를 지정하고, OS 는 shmid 로 세그먼트를 식별한다.

## Evidence

- `shmget` 으로 만들거나 찾고, 쓰려는 프로세스는 attach(`shmat`)해야 하며 다 쓰면 detach 한다. 다른 프로세스가 만든 세그먼트도 attach 하면 접근할 수 있다.
- key 는 애플리케이션 레벨 식별자라 기준값 + 오프셋, 접두어·시퀀스 같은 규칙으로 중복을 피한다.
- `ipcs -am` 으로 생성된 세그먼트와 attach 수를 조회한다.
- 세그먼트는 프로세스가 죽어도 남는다. 공유 메모리에 올리는 구조체 레이아웃이 바뀐 새 바이너리를 띄울 때는 기존 세그먼트를 지우고 다시 만들어야 한다.
- 공유 메모리 위에 링 버퍼 형태의 메시지 큐를 두고 SEND/RECEIVE 인덱스 차이로 처리할 메시지 수를 계산하는 IPC 도 흔하다.
- 동시 접근은 mutex·세마포어로 보호한다.
