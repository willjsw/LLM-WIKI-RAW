# AI-Native SDLC — 병목이 코드에서 사람 속도 단계로 이동한다

## Definition

AI-Native SDLC는 에이전트가 코드를 빠르게 생산하면 기획·리뷰·배포 같은 사람 속도 단계가 병목이 된다는 전제에서, SDLC 전체를 에이전트 중심으로 재배치하되 결정과 책임은 사람이 쥐는 개발 프로세스다.

## Evidence

- 6단계와 산출물: Plan(`intent.md`) → Design(`spec.md`) → Build(`plan.md`, 코드) → Test(PR에 검증 증거) → Deploy(AI 리뷰 + 승인 게이트) → Maintain(모니터링이 다시 `intent.md` 생성)
- 단계마다 선행·후행 지표를 둔다. 예: 1회 구현으로 머지되는 비율, 머지된 diff와 계획의 일치도, CI 첫 통과율, 첫 리뷰까지 시간, 반복 장애율
- Test 원칙: 측정 가능한 목표("테스트 전부 통과", "스크린샷이 목업과 일치"), 검증을 한 줄 명령으로 묶어 기록, 버그는 실패하는 테스트부터, 에이전트는 테스트 파일 편집 금지
- 병렬 세션의 한계는 한 사람이 리뷰할 수 있는 양이다
- 사람의 역할은 코드 생산에서 오케스트레이션·리뷰·거버넌스로 이동한다
- 현실적 진입점은 plan mode + 관례 파일 + 검증 명령 한 줄이다. 기획·설계 단계 변경은 조직 프로세스 변경이 필요해 무게가 다르다
