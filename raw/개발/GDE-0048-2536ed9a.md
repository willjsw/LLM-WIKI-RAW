# 정책 테이블 기반 PostgreSQL 파티션 사전 생성 함수 만들기

## Purpose

파티션 대상 테이블과 단위를 정책 테이블로 관리하고, 하루 한 번 호출하는 함수가 미래 파티션을 미리 만들어 두게 한다.

## Steps

1. 정책 테이블에 `schema_name`, `table_name`, `granularity`(DAY/MONTH), `lookahead_count`, `enabled`를 둔다.
2. 실행 함수 시작 시 `gen_random_uuid()`로 run_id를 발급해 이번 실행의 로그를 묶는다.
3. `enabled = true`인 정책 행을 FOR 루프로 돈다.
4. `0 .. coalesce(lookahead_count, 1)`만큼 반복하며 DAY면 `CURRENT_DATE + i day`, MONTH면 `CURRENT_DATE + i month`로 기준일을 계산한다. 정의되지 않은 단위는 `CONTINUE`로 건너뛴다.
5. 파티션이 없을 때만 만드는 보조 함수(`fn_ensure_partition(schema, table, granularity, anchor_date, run_id)`)를 `PERFORM`으로 호출한다. PL/pgSQL에서 반환값을 쓰지 않는 함수 호출은 `PERFORM`을 쓴다.
6. 스케줄러에서 매일 1회 실행 함수를 호출한다.
7. 파티션 대상 스키마가 여러 개면 스키마마다 함수를 두지 말고 관리 스키마 한 곳의 함수로 작업 주체를 모은 뒤 대상을 정책 테이블에 등록한다. 스키마별 함수 구조에서는 일부 스키마가 파티셔닝되지 않는 문제가 있었다.
