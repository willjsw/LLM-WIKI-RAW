# Redis Stream 해시 파티셔닝으로 Active-Active 순서 보장

## Definition

Redis Stream 에는 토픽·파티션 개념이 없으므로 `hash(세션 또는 대화 ID) mod N` 으로 파티션 스트림을 N 개 만들고 파티션마다 처리자를 하나만 둔다. 한 세션의 메시지는 항상 한 처리자로 가므로 락이나 리오더 버퍼 없이 순서와 원자성이 보장되고, 여러 인스턴스를 동시에 운영(Active-Active)할 수 있다.

## Evidence

- Kafka 토픽 파티션과 같은 개념을 키 이름으로 흉내 낸다(`<prefix>:{p}`).
- 파티셔닝이 없으면 공용 컨슈머 그룹에 후단 세션 분산 락을 붙여야 해 복잡하고 느리다. Active-Standby 를 택하던 이유가 이것이었다.
- 발행 측은 어느 인스턴스가 대화를 처리하는지 몰라도 해시값으로만 발행한다.
- 인스턴스가 다운되면 살아 있는 인스턴스가 파티션을 인수하고 ACK 되지 않은 PEL 항목을 재처리해야 한다.
- 스트림 컨슈머가 하나면 스레드 하나로 받아 별도 큐 없이 순서를 지킨다.
- 전제: 모든 발행자가 같은 해시 함수와 N 을 써야 한다(관련 관찰 참고).
