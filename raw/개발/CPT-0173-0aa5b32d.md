# 게이트웨이 신원 헤더 전파와 위조 헤더 방어

## Definition

게이트웨이가 토큰에서 꺼낸 사용자·테넌트 정보를 `X-*` 커스텀 헤더로 다운스트림에 넘기는 방식이다. 이때 클라이언트가 같은 이름의 헤더를 직접 실어 보내는 위조를 막으려고 인증 전에 해당 헤더를 지우고, 주입할 때도 지운 뒤 세팅한다.

## Evidence

- 전달 헤더 예: `X-AUTH-TYPE`, `X-PRINCIPAL-ID`, `X-TENANT-KEY`, `X-TENANT-ID`, `X-USER-ID`, `X-USER-ROLE`, `X-LOGIN-ID`, `X-SCHEMA-NAME`. 인증 방식 공용 헤더와 JWT 전용 헤더를 나누고, `X-AUTH-TYPE`으로 JWT/API Key 경로를 구분한다.
- 필터 순서: 요청 추적 → 감사 로그 → 헤더 정리(HeaderClear) → 인증 예외 경로 표시 → JWT 인증. 헤더 정리가 인증보다 먼저 실행된다.
- 주입 함수는 `headers.remove(name)` 후 `headers.set(name, value)`를 호출하고, 값이 null이면 세팅하지 않는다(빈 문자열 금지).
- 실측: 클라이언트가 `X-USER-ROLE`, `X-LOGIN-ID`에 임의 값을 넣어도 게이트웨이 값으로 덮였다.
- 정리 대상 헤더 목록을 컴포넌트로 관리하면 여러 필터가 같은 목록으로 일괄 제거할 수 있다.
