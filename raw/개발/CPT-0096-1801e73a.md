# 화면 캡처로만 회수되는 DB 검증 쿼리 설계

## Definition

결과를 파일로 반출할 수 없고 화면 사진으로만 받을 수 있는 DB 에서는, 검증 쿼리가 추가 질의 없이도 차이와 수정 방법을 알 수 있는 정보를 한 화면에 내도록 설계한다.

## Evidence

- 파일 하나 = SELECT 한 문장. 뷰·임시 테이블·변수·반복문·DO 블록을 쓰지 않는다(운영 툴이 막는다).
- 기대값은 정본을 설치한 로컬 DB 카탈로그에서 뽑아 하드코딩한다. 사람이 눈으로 옮기지 않는다.
- 첫 파일은 요약: 환경(버전·DB·계정·시각·기준 커밋)과 항목별 검사 건수 / PASS 아닌 건수. 가장 먼저 실행하고 첫 사진으로 받는다.
- 모든 파일이 같은 컬럼(번호, 항목, 대상, 결과, 기대값, 실제값, 힌트)을 낸다. 결과 값은 PASS·누락·초과·다름·허용.
- 상세 파일은 PASS 가 아닌 행만 낸다. 요약 1행만 나오면 전부 PASS 다.
- 기대값·실제값은 길이를 잘라(예: 200자) 화면에 들어가게 한다.
- 개인정보 시드 컬럼은 값 대신 해시 앞자리로 비교·출력한다. 설치 시점에 정해지는 컬럼은 비교에서 뺀다.
- 정본에 없는 객체·중복·stale 객체를 '초과'로 잡는다. 다른 솔루션 소유 객체는 '허용'으로 행을 남긴다.
- 문자셋이 CP949 인 툴이면 범위 밖 문자를 유니코드 이스케이프(`U&'\2014'`)로 쓴다. XML 기능 없이 빌드된 서버를 고려해 XML 함수를 쓰지 않는다.
- 검증 쿼리가 결함을 실제로 잡는지 로컬 DB 에 결함을 일부러 넣어 확인한다.
