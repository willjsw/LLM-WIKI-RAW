# 채널 독립 채팅 구조에서 게이트웨이와 코어 서버의 책임 분리

## Definition

외부 채팅 채널마다 다른 프로토콜·인증·메시지 형식은 게이트웨이(커넥터)가 흡수해 내부 표준 메시지로 바꾸고, 코어 채팅 서버는 채널과 무관하게 세션 관리와 메시지 저장·중계만 맡는 구조다.

## Evidence

- 흐름: 고객 브라우저 →(웹소켓 또는 HTTP)→ 게이트웨이 → Redis Stream → 채팅 서버 → 시나리오·배정·Push → 통계.
- 플랫폼 종속성은 게이트웨이로 몰고 메시지 구조는 플랫폼 독립적으로 설계한다.
- 최초 요청과 종료 흐름만 코어 로직을 타고 대화 중 메시지는 거의 그대로 중계(ByPass)한다. 상태 관리 서버는 상태 변경 시에만 거친다.
- 웹소켓을 전제해도 실제 고객 시스템과는 HTTP API 연동일 가능성이 높아 게이트웨이의 인터페이스 변환이 필수다.
- 써드파티 채널은 우리 시스템이 인증을 주관하지 않고 써드파티 인증(API Key 등)을 받아 쓰므로 인증 방식도 게이트웨이에서 채널별로 다르다.
