# Spring STOMP 목적지 라우팅과 simple broker 범위

## Definition

Spring STOMP 는 clientInboundChannel 인터셉터를 거친 프레임을 목적지 접두사로 나눠 `/pub/**` SEND 는 `@MessageMapping` 메서드로, `/sub/**`·`/user/queue/**` SUBSCRIBE 는 브로커로 보낸다. simple broker 는 인스턴스 메모리 안의 브로커라 다른 인스턴스의 구독자에게 닿지 않는다.

## Evidence

- CONNECT 인증·SUBSCRIBE 권한 검사는 `ChannelInterceptor` 에서 한다.
- `/sub/**` 는 브로커 구독자 전원에게 브로드캐스트, `/user/queue/**` 는 연결 전용 목적지로 변환되어 같은 경로를 다른 연결이 구독해도 섞이지 않는다. 1:1 응답에 쓴다.
- "요청한 연결만"과 "대화의 모든 연결"을 한 목적지로 보내려면 익명 연결에 Principal 을 심는 우회가 필요하다. 경로를 나누면 브로커 기본 동작으로 끝난다.
- 다중 인스턴스에서는 인스턴스 간 전달을 Redis Stream 같은 외부 매체가 맡고, 받은 인스턴스가 `SimpMessagingTemplate` 으로 자기 브로커에 넣는다.
- 전역 유일 ID 를 가진 리소스는 하위 경로보다 독립 경로(`/sessions/{id}`)가 발송·구독 검사가 단순하다. 접두가 겹치는 경로 체계는 구독 검사를 복잡하게 만든다.
