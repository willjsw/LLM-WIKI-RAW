# git 을 다루는 테스트에서 리포 지역 환경 변수 격리

## Purpose

임시 git 리포를 만드는 테스트가 훅·worktree 환경에서 넘어온 `GIT_DIR` 등을 물려받아 실제 리포를 오염시키는 것을 막고, 오염됐을 때 복구한다.

## Steps

1. 임시 리포를 만드는 모든 테스트 스크립트 첫머리에 `unset $(git rev-parse --local-env-vars 2>/dev/null)` 을 둔다. git 이 "이 리포에만 해당한다"고 정한 변수 목록(GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE, GIT_COMMON_DIR, GIT_OBJECT_DIRECTORY 등)을 내주므로 목록을 하드코딩하지 않는다.
2. 테스트 러너 한 곳이 아니라 각 테스트 파일에 둔다. 테스트는 훅을 거치지 않고 단독으로도 실행되므로 스스로 격리해야 한다.
3. 회귀 테스트를 추가한다. 임시 디렉터리에 가짜 리포와 그 worktree 를 만들고, `GIT_DIR` 을 그 리포로 가리킨 채 테스트를 전부 돌려 가짜 리포의 `core.bare` 와 브랜치 목록이 그대로인지 확인한다.
4. 이미 오염됐다면 `git --git-dir=<리포>/.git config core.bare false` 로 복구한다.
5. `git branch --list <테스트가 만드는 브랜치들>` 과 `git worktree list` 로 남은 흔적을 확인하고 정리한다.
6. 대안으로 거론되는 방법은 쓰지 않는다. 훅에서만 비우면 직접 호출 경로가 남고, 모든 git 호출에 `--git-dir`·`--work-tree` 를 붙이면 빠뜨리기 쉬우며, worktree 에서 검증을 안 하는 것은 증상 회피다.
