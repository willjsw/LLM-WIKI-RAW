# Flyway로 여러 앱이 공유하는 스키마를 수동 마이그레이션하기

## Purpose

여러 애플리케이션이 같은 DB 스키마를 공유할 때 Flyway를 앱과 분리된 별도 실행 단위로 두고 스키마 변경을 버전 관리한다.

## Steps

1. `db/sql/<스키마명>/Vn__설명.sql` 구조로 스키마별 버전 파일을 둔다.
2. 접속 정보는 `.env`에 넣고 커밋하지 않는다. compose에서 Flyway 서비스는 별도 profile로 두어 `docker compose up`에 딸려 뜨지 않게 한다.
3. `docker compose run --rm flyway info`로 적용 현황을 본다.
4. 최초 1회 baseline을 잡는다. 객체가 이미 있는 운영 스키마는 `-baselineVersion=<현재 버전> baseline` 후 `migrate`, 빈 스키마는 `-baselineOnMigrate=true migrate`. baseline 없이 `migrate`하면 기존 객체가 있는 스키마에서 거부된다.
5. 변경은 다음 번호의 새 파일로 추가하고 스키마 한정자는 `${flyway:defaultSchema}.` 같은 placeholder로 쓴다. 변형 스키마는 파일 복제 없이 대상 스키마 설정만 바꿔 같은 SQL을 재적용한다.
6. `migrate`로 적용하고 `validate`로 SQL과 history 정합성을 확인한다.
7. 앱 계정 권한 부여는 `afterMigrate__*.sql` 콜백에 둔다. 매 migrate 후 실행되고 history에는 남지 않는다.
8. 되돌릴 때는 이미 적용된 파일을 고치지 말고(해시 검증 실패) 되돌리는 내용을 담은 새 버전 파일로 forward-fix한다. `cleanDisabled=true`로 스키마 전체 삭제를 막아 둔다.
