# 아티팩트로 단계를 잇는 SDLC — intent, spec, plan, PR

## Definition

아티팩트로 잇는 SDLC는 단계 전환을 회의 대신 저장소에 커밋되는 마크다운 파일(`intent.md → spec.md → plan.md → PR`)로 처리하는 방식이다. 각 파일이 다음 단계의 입력이고, 사람은 만들기보다 읽고 고치고 통과시키는 역할을 한다.

## Evidence

- 배경: 구현이 하루로 줄어도 앞뒤 회의가 몇 주면 리드타임은 그대로다
- intent.md 구조: 문제 / 기대 결과 / 영향받는 사용자·시스템 / 제약 / 미결 질문
- spec 작성 세션에 조직 정책(skills)을 함께 넣어 정책 위반을 스펙 작성 시점에 플래그한다
- 계획을 커밋해 두면 머지된 diff가 계획과 얼마나 일치하는지 측정할 수 있고, 불일치가 크면 계획 단계가 부실했다는 신호다
- 얻는 것: git 히스토리가 곧 감사 추적, 파일만 읽으면 되는 컨텍스트 이관, 커밋 시각 차이로 단계 소요 시간 측정, 진실의 원천 단일화
- 주의: 작은 변경까지 3종 세트를 강제하면 관료제가 마크다운으로 옮겨갈 뿐이므로 규모 기준을 둔다. 기존 티켓 시스템과 병행하면 마크다운을 원본으로 두고 링크만 건다(두 곳에 쓰면 둘 다 신뢰를 잃는다)
