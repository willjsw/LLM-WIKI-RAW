# API Key 해시 저장과 게이트웨이 캐싱

## Definition

API Key 원문을 저장하지 않고 SHA-256 해시로 DB에 저장한 뒤, 게이트웨이는 요청 키를 해시해 비교하고 조회 결과를 Redis 등에 캐싱하는 방식이다.

## Evidence

- DB가 유출돼도 키 원문이 드러나지 않는다.
- 매 요청 DB 조회를 피하려고 Redis에 캐싱한다.
- 남은 논점: 존재하지 않는 키로 반복 요청하면 캐시 미스마다 DB 조회가 발생해 부하가 생긴다. 없는 키를 짧게 캐싱(블랙리스트)할지, 키 갱신 직후 캐시 무효화를 어떻게 맞출지를 함께 설계해야 한다.
- 요청마다 RequestId를 발급해 감사 로그와 다운스트림 로그를 묶으면 키별 추적이 쉬워진다.
