# SIP REGISTER Digest 인증과 재등록 타이머 설정

## Purpose

단말(UAC)이 Registrar 에 인증 등록하고 바인딩이 끊기지 않게 갱신하는 절차를 올바르게 구현하거나 점검한다.

## Steps

1. 인증 정보 없이 REGISTER 를 보낸다. 서버마다 realm·qop·알고리즘이 다르고 nonce 는 서버가 만든 일회성 난수라 미리 알 수 없기 때문이다.
2. `401 Unauthorized` 의 `WWW-Authenticate` 에서 realm, nonce, qop 를 읽는다. 중간 프록시가 요구하면 `407` + `Proxy-Authenticate` 이고 응답 헤더는 `Proxy-Authorization` 이다. 둘 다 걸리면 두 헤더를 모두 붙인다.
3. 비밀번호와 nonce 로 response 해시를 계산해 `Authorization` 헤더를 붙여 다시 보낸다. 비밀번호 자체는 전송되지 않는다.
4. 재전송 시 CSeq 는 반드시 올리고 Call-ID 와 From tag 는 유지한다. CSeq 를 안 올리면 서버가 중복 요청으로 보고 401 을 무한 반복한다.
5. 200 OK 의 Contact `expires` 값을 실제 만료로 쓴다. 요청한 값(예: 3600)이 아니라 응답 값(예: 600)으로 재등록 타이머를 다시 계산한다. 무시하면 서버 만료 후 재등록 전까지 착신이 안 된다.
6. 만료 시간의 50~90% 지점에서 재등록한다(예: 600초면 300~540초). 만료 직전에 보내면 유실 시 재시도 여유가 없다.
7. 왕복을 줄이려면 받은 nonce 를 캐시해 다음 등록부터 처음부터 Authorization 을 붙인다. nonce 가 만료됐으면 서버가 `401` + `stale=true` 를 주므로 비밀번호 재입력 없이 새 nonce 로 재계산한다.
8. `423 Interval Too Brief` 를 받으면 응답의 `Min-Expires` 값으로 다시 요청한다. `403` 은 계정·realm 불일치이므로 재시도하지 말고 설정을 확인한다.
9. 종료 시에는 `expires=0` 으로 해제해 서버가 즉시 바인딩을 지우게 한다.
10. 보안: 가능하면 TLS 를 쓰고(Digest 만으로는 도청·변조를 못 막음), nonce 수명을 짧게, 연속 실패를 차단하고, 로그에 비밀번호·해시 원문을 남기지 않는다.
