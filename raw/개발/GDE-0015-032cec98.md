# Thread Dump로 병목 원인을 찾는 3가지 패턴

## Purpose

응답 지연이나 행(Hang) 상황에서 Thread Dump를 읽어 병목의 진짜 원인 코드를 찾는다.

## Steps

1. 시간 간격을 두고 덤프를 2개 이상 뜬다
2. 패턴 #1(BLOCKED, `waiting for monitor entry`): `waiting to lock <주소>`인 스레드를 찾고, 같은 주소를 `locked <주소>`로 가진 스레드를 검색한다. 보유 스레드의 Top Stack이 진짜 원인 코드다. 락 대상이 Class 객체면 static synchronized 메서드다
3. 패턴 #2(RUNNABLE, Top Stack `SocketInputStream.socketRead0`): 원격 서버(DB, 외부 API) 응답 지연으로 Worker Thread가 고갈된 상태다. RUNNABLE이라도 CPU를 쓰는 것이 아니므로 상태값만 보지 말고 Top Stack을 함께 본다
4. 패턴 #3(WAITING, Top Stack `Object.wait`): 커넥션 풀 같은 Pool 자원이 고갈되어 대기하는 상태다. 커넥션을 오래 붙잡은 다른 스레드(대개 패턴 #2)를 찾아 근본 원인으로 본다
5. 상태별 분포와 데드락 여부는 덤프 분석 도구로 자동 집계해 확인한다
