# Java 스레드 상태와 Thread Dump 읽는 법

## Definition

Java 스레드 상태(NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED)는 OS 스레드 상태가 아닌 VM 상태다. 모니터의 Entry Set에서 락을 기다리면 BLOCKED, 락을 얻은 뒤 `wait()`로 Wait Set에 들어가면 WAITING/TIMED_WAITING이 된다.

## Evidence

- WAITING/TIMED_WAITING에서 깨어나도 모니터를 다시 얻어야 하므로 곧바로 RUNNABLE이 아니라 BLOCKED를 거칠 수 있다
- 덤프 헤더: 스레드 이름, daemon 여부, 우선순위, tid(JVM 내부 ID), nid(OS 네이티브 스레드 ID), 상태
- 락 표기: `- locked <주소>`(보유), `- waiting to lock <주소>`(진입 대기), `- waiting on <주소>`(wait 중)
- `Object.wait()`는 모니터를 쥔 상태에서 호출하고 진입 시 반납하므로 덤프에 waiting on과 locked가 같은 객체로 함께 찍힌다
- 덤프는 반드시 시간 간격을 두고 2개 이상 떠서 비교한다. 두 덤프 비교로 장기 수행 스레드를 찾는 분석 도구가 있다
- 생성: `jcmd <PID> Thread.print`, `jstack <PID>`, `kill -3 <PID>`
