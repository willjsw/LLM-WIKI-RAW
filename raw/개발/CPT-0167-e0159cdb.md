# 대상 크기를 받지 않는 문자열 복사 헬퍼의 위험

## Definition

문자열 복사 헬퍼가 대상 버퍼 크기를 인자로 받지 않으면 내부에서 길이를 검사할 방법이 없다. 안전을 암시하는 이름(예: "NULL 이 아닐 때만 복사")은 NULL 만 막을 뿐 길이 위험을 가리므로, 외부 입력이 닿는 복사는 반드시 대상 크기를 함께 넘기는 형태로 만든다.

## Evidence

- 사례: NULL 방어만 하고 `strcpy` 를 호출하는 헬퍼가 20여 곳에서 쓰였고, 원격 SIP 헤더 값(To URI, Call-ID, Contact, From 호스트)이 길이 제한 없이 129바이트 필드로 복사됐다.
- 그 필드는 공유메모리 배열 원소 안에 있어, 긴 헤더를 담은 요청 하나로 인접 원소(다른 단말의 컨텍스트, 상태값)를 덮을 수 있었다. 원격에서 트리거 가능한 공유메모리 오염이라 심각도 최상으로 분류됐다.
- 129바이트 필드를 128바이트 스택 버퍼로 옮기는 1바이트 초과 사례도 있었다.
- 수정안: 크기 인자를 받는 버전과 `sizeof(dst)` 를 자동으로 넘기는 매크로(`#define STR_CPY_NN(dst, src) str_cpy_nn((dst), (src), sizeof(dst))`)로 교체한다. 호출부가 많아 작업량이 크므로 파서의 길이 상한을 먼저 확인하고 계획을 세운다. `strncpy` 로 바꿀 때는 소스가 NULL 일 수 있는지와 NUL 종단을 함께 확인한다.
- 검증: AddressSanitizer 빌드와 긴 헤더(예: 200자 URI) 입력 시나리오로 재현한다.
