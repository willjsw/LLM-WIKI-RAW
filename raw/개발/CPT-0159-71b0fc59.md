# SIP 의 Transaction, Dialog, Session 세 층

## Definition

SIP 의 상태는 범위가 다른 세 층으로 나뉜다. Transaction 은 요청 하나와 그 응답들의 묶음(수 초), Dialog 는 두 UA 사이의 지속 관계(통화 전체), Session 은 SDP 로 기술된 미디어가 흐르는 상태다.

## Evidence

- Transaction 식별: Via 의 `branch`(RFC 3261 방식은 `z9hG4bK` 로 시작) + sent-by + CSeq 메서드. 구형은 To/From/Call-ID/CSeq/Request-URI 조합으로 추정 매칭한다.
- Dialog 식별: `Call-ID` + `From tag` + `To tag`.
- 트랜잭션 상태 머신은 INVITE 클라이언트/서버, non-INVITE 클라이언트/서버 4종이고 INVITE 쪽이 ACK 처리 때문에 가장 복잡하다.
- INVITE 만 3-way(요청 → 최종 응답 → ACK)다. 2xx 에 대한 ACK 는 트랜잭션이 아니라 별도 요청으로 취급되어 UA 가 재전송을 책임진다.
- 한 단말은 상황에 따라 UAC(요청을 보내는 쪽)도 UAS(받는 쪽)도 된다. 예: 건 쪽이 UAC 지만 상대가 먼저 BYE 를 보내면 그때는 상대가 UAC 다.
- CSeq 는 다이얼로그 안에서 요청마다 증가하고, ACK·CANCEL 은 대상 INVITE 와 같은 번호에 메서드만 다르다.
