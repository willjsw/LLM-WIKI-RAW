# STOMP over WebSocket 계층과 프레임 규칙

## Definition

STOMP over WebSocket 은 HTTP Upgrade 로 연 WebSocket 통로 위에 STOMP 1.2 프레임(명령·헤더·본문, NUL 종료)을 하나씩 싣는 구조다. WebSocket 은 통로, STOMP 는 목적지(destination) 기반 우편 규약, JSON 본문은 업무 내용이다.

## Evidence

- 계층: TCP/TLS → HTTP/1.1 Upgrade(최초 1회, 101) → WebSocket(텍스트 프레임 하나에 STOMP 프레임 하나) → STOMP 1.2 → JSON 본문.
- 프레임 형식: `COMMAND` 줄, `header:value` 줄들, 빈 줄, 본문, NUL(0x00).
- 응답 규칙
  - SEND 에는 응답이 없다. 결과는 구독 경로로 MESSAGE 가 온다. 결과 경로를 먼저 구독하고, 요청과 결과를 잇는 키(`requestId`, `clientMessageId`)를 본문에 둔다.
  - SUBSCRIBE 에도 응답이 없다. 등록 시점을 알아야 하면 `receipt` 헤더를 달고 RECEIPT 를 기다린다. "구독 먼저, 이력 조회 나중" 같은 순서 보장은 RECEIPT 를 받은 뒤에야 엄밀하다.
  - ERROR 는 보낸 뒤 서버가 연결을 닫는다. 업무 오류는 MESSAGE 본문의 결과 코드로 알린다.
- destination 접두사(`/pub`·`/sub`·`/app`·`/topic`)의 뜻은 STOMP 가 아니라 서버 설정이 정한다. 접두사 체계가 곧 팀 컨벤션이다.
- 구독은 연결에 속한다. 재연결하면 CONNECT 부터 구독까지 다시 한다.
