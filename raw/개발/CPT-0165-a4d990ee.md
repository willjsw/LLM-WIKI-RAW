# 라이브러리 getter 반환값의 메모리 소유권

## Definition

C 라이브러리의 getter 는 새로 할당한 버퍼를 반환하는 할당형(호출자가 해제해야 함)과 내부 객체의 필드 주소를 반환하는 참조형(해제하면 double free)으로 나뉜다. 이름만으로는 구분할 수 없으므로 누수 판정과 해제 코드 작성 전에 구현을 읽어 함수별로 확인해야 한다.

## Evidence

- 분석한 SIP 라이브러리에서는 URI·Authorization 류 getter 가 `calloc(1, strlen+1)` 버퍼를 반환해 해제가 필수였고, Call-ID·헤더 파라미터·tag·CSeq 메서드·URI user/host 류는 메시지 객체 내부 주소를 반환해 해제가 금지였다. 같은 라이브러리 안에서 규칙이 섞여 있었다.
- 확정 누수 사례: 할당형 getter 결과를 임시 변수에 받아 쓰고 해제하지 않음(요청마다 누수), 할당형 getter 를 다른 함수의 인자로 바로 넘기고 반환값을 버림.
- 오탐 사례: 참조형 getter 결과를 해제하지 않은 코드는 정상이다. 정적 분석 도구가 흔히 오탐하므로 "누수가 아닌 것"과 근거를 따로 기록해 둔다.
- 확인 방법: 라이브러리 소스에서 반환값의 출처(`calloc`/`malloc` vs 구조체 필드 주소)를 추적하고, 다른 모듈이 같은 getter 결과를 `free` 하는 코드를 교차 근거로 삼는다. 결과를 함수별 표(반환 성격, 해제 필수/금지, 해제 함수)로 남긴다.
- 파서가 만든 구조체(URI 파싱 결과 등)는 전용 해제 함수로 정리해야 하는 경우도 있다.
