# 세션 확정 후 집계로 넘기는 핸드오프 패턴

## Definition

수집기는 콜 세션이 "확정"되는 조건까지만 판단하고, 확정된 세션을 작업 테이블과 스트림으로 집계 잡에 넘기는 구조다. 수집과 집계의 책임을 나눠 집계 잡은 확정된 데이터만 다룬다.

## Evidence

- 확정 조건 예: 세션 안 모든 콜이 종료되고 quiet window가 지남 + 응대한 상담사의 후처리(ACW) 종료. 확정 시각은 max(콜 종료, 후처리 종료)로 잡는다.
- 확정되면 작업 테이블에 READY로 넣고(`on conflict (session_id) do nothing`) 세션 패키지를 스트림으로 발행한다. 집계는 별도 잡이 15분/일 단위로 한다.
- 확정 뒤 늦은 이벤트가 오면 확정 결과는 바꾸지 않고 패키지만 재발행한다.
- 대비: DB 프로시저가 주기적으로 terminated 범위를 긁어 가는 방식은 늦게 온 이벤트나 후처리 시간을 반영하기 어렵다.
- READY인데 집계 큐에 들어가지 않은 건을 잡는 reconciliation 스케줄이 꺼져 있으면 누락을 로그로만 알게 된다.
