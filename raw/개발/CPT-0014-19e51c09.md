# Quartz JDBC JobStore의 잡 등록 흐름과 클러스터링

## Definition

Quartz의 JDBC JobStore는 잡과 트리거를 QRTZ_ 테이블에 트랜잭션으로 저장하고, QRTZ_LOCKS 행 락으로 여러 노드의 동시 변경을 막는다. 클러스터 모드에서는 같은 트리거가 한 노드에서만 실행된다.

## Evidence

- 등록 순서: `scheduleJob(JobDetail, Trigger)` → StdScheduler(Facade) → QuartzScheduler(Core) → `JobStoreTX.storeJobAndTrigger`.
- 저장 구간: 트랜잭션 시작 + `SELECT ... FOR UPDATE` on `QRTZ_LOCKS` → `QRTZ_JOB_DETAILS` INSERT → `QRTZ_TRIGGERS` INSERT → 크론 트리거면 `QRTZ_CRON_TRIGGERS` INSERT → 커밋과 락 해제.
- 저장 후 `signalSchedulingChange()`로 대기 중인 QuartzSchedulerThread를 깨워 다음 실행 시각을 다시 계산하게 한다.
- `isClustered=true`인 Quartz 잡은 다중 인스턴스에서 중복 실행되지 않지만, 같은 애플리케이션 안의 Spring `@Scheduled` 메서드는 클러스터링 대상이 아니어서 인스턴스마다 실행된다. 이중화 환경에서 주기 작업은 한쪽 방식으로 통일한다.
- 이중화 환경에서 Quartz를 쓰는 이유는 활성 노드를 DB 락으로 자동 결정할 수 있기 때문이다.
