# Liquibase 와 Flyway 의 변경 식별과 운영 기능 차이

## Definition

두 도구 모두 변경분을 순서대로 쌓고 DB 안 이력 테이블에 적용 이력을 남기는 마이그레이션 도구다. Liquibase 는 changelog 안 changeset 을 id·author·파일 경로로 식별하고 적힌 순서대로 실행하며, Flyway 는 파일 하나가 변경 하나이고 파일명 버전 번호 순으로 실행한다.

## Evidence

- 이력 테이블: Liquibase DATABASECHANGELOG + 잠금 테이블, Flyway flyway_schema_history. 둘 다 체크섬으로 적용 후 변경을 감지한다.
- 반복 적용 객체(뷰·함수): Liquibase `runOnChange`, Flyway `R__` 반복 마이그레이션.
- 환경별 선택 실행: Liquibase contexts·labels. Flyway 는 별도 필터가 없어 locations 를 환경마다 달리 준다.
- 사전 조건: Liquibase preconditions, Flyway 는 콜백·스크립트로 대체.
- 기존 DB 도입: Flyway baseline, Liquibase 는 이미 적용됨 표시 방식(사용 버전 문서로 확인 필요).
- SQL 만 출력: Liquibase `update-sql` 은 Community 에 포함, Flyway `dryRunOutput` 은 상용 에디션 기능으로 표기돼 있다.
- Liquibase offline 모드는 이력을 CSV 로 관리하는데, `update-sql` 을 offline 으로 돌리면 그 SQL 이 실제 적용될 것으로 가정하고 CSV 에 바로 추가한다. 반려·부분 실행되면 CSV 가 실제와 어긋난다.
- 라이선스·에디션 정책은 바뀌고 있다(작성 시점에 Liquibase 5.0 Community 의 FSL 전환 등 확인). 도입 시 사용 버전의 공식 문서와 라이선스 원문을 다시 확인한다.
