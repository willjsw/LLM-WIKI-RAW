# 실행 순서가 보장되지 않는 결재 환경의 증분 DDL 작성 원칙

## Definition

결재 건마다 따로 실행되고 그 사이 순서가 보장되지 않는 환경에서는, 각 증분 SQL 파일이 어떤 순서로 실행돼도 같은 결과를 내도록 의존하는 변경을 한 파일에 모으고 파일 안은 순수 DDL 로만 쓴다.

## Evidence

- 예: 컬럼 이름 변경과 그 컬럼을 참조하는 뷰 재생성은 같은 파일에 순서대로 쓴다.
- 툴이 AutoCommit 하므로 BEGIN/COMMIT 같은 트랜잭션 제어를 넣지 않는다. 넣어 두면 Dry-Run(트랜잭션 + ROLLBACK)이 실제 반영이 된다.
- `DROP ... CASCADE` 대신 함께 지워질 의존 객체를 명시적으로 DROP·재생성한다. 예상 밖 의존이 있으면 오류로 멈추게 하려는 것이다.
- DROP 후 재생성한 객체는 GRANT·COMMENT 를 같은 파일에서 다시 준다.
- ALTER 로 가능하면 DROP·재생성하지 않는다(데이터 보존).
- 소유자 지정(OWNER TO)은 쓰지 않고 실행 계정이 소유하게 한다. 롤 생성·멤버십처럼 실행 계정 권한 밖인 변경은 파일을 따로 뺀다.
- 순서 무관을 증명하려면 Dry-Run 을 정순 1회, 역순 1회(각각 별도 트랜잭션) 돌려 둘 다 오류 없이 같은 결과인지 본다.
