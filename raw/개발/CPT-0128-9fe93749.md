# 암복호화 계층의 실패와 비밀 취급 계약

## Definition

암복호화 계층은 실패했을 때 원문을 돌려주지 않고 반드시 예외를 던지며, 로그·예외 메시지·toString 어디에도 키·평문·암호문을 남기지 않고 원인 분류만 남긴다.

## Evidence

- 실패 시 원문을 반환하면 평문이 "암호화된 척" 조용히 저장된다.
- 키 형식 오류 메시지에 입력값을 넣지 않는다. 그 입력값이 곧 키다. 길이·문자 종류만 알린다.
- 벤더 라이브러리 예외의 cause 는 초기화 실패에서만 유지한다. 암복호화 실패 메시지에는 입력 데이터가 실릴 수 있다.
- 복호화 실패의 세부 원인(인증 실패인지 모드 불일치인지)은 로컬 진단용이고 외부 응답에 노출하지 않는다.
- 키 바이트 배열은 사용 직후 0 으로 덮어쓴다(힙 덤프 노출 축소). Java String 은 불변이라 소거할 수 없으므로 운영 키는 환경 변수나 KMS·Vault 로 런타임 주입한다.
- 예외 계층의 base 예외가 직접 던져질 수 있으면 catch 체인 마지막에 반드시 둔다. 키 부재처럼 생성 시점에만 나는 예외가 있으므로 fail-fast 블록에는 생성과 해석을 함께 넣는다.
- 무결성은 구현마다 다르다. AEAD 는 변조를 거부하지만 인증 없는 CBC 구현은 쓰레기 평문을 돌려줄 수 있으니 어떤 구현이 꽂히는지 확인한다.
