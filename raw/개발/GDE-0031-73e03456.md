# 평문 비밀을 저장소에서 암호문으로 바꿀 때 점검 절차

## Purpose

설정 파일의 평문 비밀번호를 암호문으로 바꾸면서 남는 노출 경로까지 닫는다.

## Steps

1. 암호문을 만들 때 평문을 명령행 인자로 넘기지 않는다. 셸 히스토리와 `ps` 에 남는다. 숨김 입력(에코 꺼짐)을 쓴다. 암호문은 인자로 넘겨도 된다.
2. 넣기 전에 같은 키로 복호화해 왕복을 확인하고, 출력은 파일·로그에 남기지 않는다.
3. 설정 파일 값을 암호문으로 교체한 뒤 평문이 남았는지 grep 한다.
4. 기동 후 실제 쿼리 1건으로 접속을 확인하고, 실패 케이스(키 없음, 다른 키, 변조된 암호문, 활성화 플래그 누락)에서 로그·예외에 키·평문이 없는지 본다.
5. 애플리케이션 로그 전체를 평문 비밀번호로 grep 해 0건인지 확인한다.
6. Actuator `env`·`configprops` 노출 여부를 점검한다.
7. 비밀이 자식 프로세스 인자로 넘어가면 `ps` 에 보이므로 환경 변수나 파일로 전달하는 별도 과제로 남긴다.
8. 이미 git 히스토리에 커밋된 평문은 파일을 바꿔도 지워지지 않는다. 해당 계정 비밀번호를 교체(rotate)하는 것이 실질 조치이고, 공유 브랜치 히스토리 재작성은 별도 합의가 필요하다.
