# Redis Stream 소비 설정이 결정하는 전달 보장 수준

## Definition

Redis Stream 소비자의 전달 보장 수준은 ACK 시점, consumer group 이름의 고정 여부, 시작 offset, PEL 재처리 유무의 조합으로 정해진다. 처리 전에 ACK하거나 autoAcknowledge를 쓰고 PEL을 재처리하지 않으면 at-most-once다.

## Evidence

- 처리(dispatch) 전에 수동 ACK: 처리 중 장애가 나면 그 메시지는 잃는다 → at-most-once.
- `autoAcknowledge(true)`: 읽는 즉시 ACK되므로 역시 at-most-once.
- 고정 group/consumer 이름 + 그룹 생성 시 offset `0`, 이후 `>`: 재기동 후 마지막 위치부터 이어 읽을 수 있다.
- 기동마다 랜덤 UUID group + 시작 offset `$` + 종료 시 group 삭제: 기동 이전 메시지를 읽지 않으므로 다운타임 동안의 이벤트가 구조적으로 유실된다.
- 인스턴스마다 group이 다르면 각 인스턴스가 전체 이벤트를 받는다(broadcast). 같은 group과 같은 consumer 이름을 공유하면 메시지를 나눠 받으므로 메모리 상태 기반 처리가 깨진다.
- 로그에 "XPENDING으로 복구 가능"이라고 적혀 있어도 PEL 재처리 코드가 없으면 실제로 복구되지 않는다.
- at-least-once로 올리려면 처리 후 ACK, PEL 재처리, 메시지 단위 dedup 키가 함께 필요하다.
- 백프레셔: 내부 큐 `offer`가 실패하면 유실, `put`은 블로킹되어 소비 속도를 늦춘다.
