# 멱등 키 유무에 따른 외부 전송 재시도 규칙

## Definition

멱등 키가 없는 외부 쓰기 API 는 응답 타임아웃 뒤 재시도하면 중복 처리가 생길 수 있으므로, 연결 실패처럼 요청이 확실히 도달하지 않은 오류에만 재시도한다. 서버가 일련번호·eventId 로 중복을 거절하는 API 는 자유롭게 재시도한다.

## Evidence

- 타임아웃은 재시도하지 않고 실패로 상위에 보고한다.
- 순서를 지키려면 실패 메시지를 꺼내지 않고 큐 맨 앞에 둔 채 재시도하고, 뒤 메시지는 앞 메시지 결과가 확정될 때까지 보내지 않는다.
- 서킷 브레이커로 짧은 창(예: 최근 10초) 안에서 N 회 실패하면 요청을 멈췄다가 일정 시간 뒤 다시 시도한다. Jitter 로 복구 직후의 재시도 폭주를 막는다.
- 계속 실패하면 TTL·DLQ 로 빼고 뒤 메시지를 진행한다. 이때 엄격 순서(앞이 실패하면 뒤도 보류)와 메신저식(실패 표시 후 진행) 중 하나를 정책으로 고른다.
- 인메모리 재시도 큐는 인스턴스가 죽으면 사라지므로 상한과 유실 허용 범위를 정해야 한다.
- 채널당 토큰버킷으로 사용량 한도를 지키고, 대기 한도를 넘긴 건은 실패 처리한다.
