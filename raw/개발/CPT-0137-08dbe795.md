# 유닉스 시그널 종류와 처리 원칙

## Definition

시그널은 OS 가 프로세스에 보내는 비동기 인터럽트다. 대부분은 핸들러로 잡거나 무시할 수 있지만 SIGKILL(9)은 잡을 수도 막을 수도 없다.

## Evidence

- SIGTERM 은 `kill` 의 기본 시그널로 정상 종료 요청이다. Ctrl+C 는 SIGINT 를 보낸다.
- SIGHUP 은 터미널 끊김 신호지만 데몬에서는 설정 재로드 신호로 관례적으로 쓴다. SIGUSR1/SIGUSR2 는 애플리케이션이 자유롭게 의미를 정한다.
- 0 나누기 같은 오류도 시그널로 전달되고 처리하지 않으면 core dump 로 비정상 종료한다. 종료 전에 최소한 쓰던 자원은 정리해야 한다.
- fork 한 부모는 자식이 끝나면 SIGCHLD 를 받는다. 멀티 프로세스 구조는 자식 하나가 죽어도 나머지가 살아 있다.
- 핸들러 등록은 `signal()` 보다 동작이 명확한 `sigaction()` 을 권장한다.
- 1~15 번 시그널은 OS 간 차이가 거의 없다.
