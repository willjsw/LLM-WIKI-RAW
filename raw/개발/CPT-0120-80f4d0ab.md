# Spring STOMP 목적지 접두와 브로커 선택

## Definition

Spring 의 STOMP 지원은 목적지 접두로 흐름을 나눈다. `/app/**` 은 애플리케이션 핸들러로, `/topic/**`·`/queue/**` 는 브로커로, `/user/**` 는 특정 사용자 세션으로 간다.

## Evidence

- `/app/**`: 클라이언트 SEND 가 `@MessageMapping` 메서드로 들어간다.
- `/topic/**`(다수 대상), `/queue/**`(개인 대상)는 관례이고 브로커가 구독자에게 전달한다.
- `/user/**`: `convertAndSendToUser`, `@SendToUser` 로 특정 Principal 의 세션들에만 보낸다.
- simple broker: 인메모리·인스턴스 로컬. 설정이 간단하지만 인스턴스 간 공유가 없다.
- broker relay: RabbitMQ·ActiveMQ 같은 외부 STOMP 브로커로 중계해 인스턴스 간 공유가 되지만 운영할 인프라가 늘어난다.
- 모든 인스턴스가 아웃바운드를 전량 받고 자기 연결이 없는 메시지는 버리는 구조라면 simple broker 로도 다중 인스턴스를 처리할 수 있다.
- `ChannelInterceptor` 로 CONNECT 를 가로채 인증하고 Principal 을 정한다.
- 처리 결과나 클라이언트 메시지 ID 를 돌려줘야 하면 STOMP RECEIPT 대신 애플리케이션 이벤트로 확인을 보내는 편이 낫다.
