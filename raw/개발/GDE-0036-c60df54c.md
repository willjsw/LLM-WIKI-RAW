# AI 코딩 에이전트 컨텍스트 하네스 초기 구성 원칙

## Purpose

기존 리포에 AI 코딩 에이전트가 읽을 규칙·명세·검증 장치를 처음 구성할 때, 추측으로 채운 값과 상충 정보가 문서에 섞이지 않게 하고 에이전트 컨텍스트를 작게 유지한다.

## Steps

1. 작업을 단계로 나누고 단계마다 완료 보고(예: 디렉터리 트리, 생성 파일 목록과 근거, TBD 목록) 후 승인을 받고 다음 단계로 간다.
2. 담당 범위를 모듈 하나로 한정하고 인접 모듈은 맥락 이해용으로만 참조한다. 범위 문서에는 "여기서 만들지 않는 것"을 반드시 적는다.
3. 근거 우선순위를 정한다(예: ADR > docs > 원본 노트 > 대화 맥락). 원본은 읽기 전용으로 다룬다.
4. 문서 간 충돌은 임의로 판단하지 않고 산출물 상단 "Open Questions" 절에 쟁점과 출처를 기록한다.
5. 원본에서 확인되지 않은 값(버전, 포트, 엔드포인트, 접속 정보, 담당자)은 `<!-- TBD: 확인 필요 -->` 마커로 남긴다. 빌드 파일·소스 트리에서 직접 확인한 값만 쓴다.
6. 명칭이 혼재하면 확정 명칭과 옛 별칭의 매핑을 용어 사전의 Deprecated Aliases 절에 두고 신규 산출물에는 확정 명칭만 쓴다.
7. 매 세션 전량 로드되는 지침 파일은 200줄 이내로 유지한다. 특정 작업용 상세 규칙은 docs 로 분리하고 "언제 읽어야 하는지"와 함께 링크한다. 명령은 실재하는 것만 적는다.
8. 환경 문서에는 항목명과 취득 경로만 쓴다. 접속 정보·토큰·계정은 리포에 평문으로 남기지 않는다.
9. 의존성 규칙은 실제 패키지 경로 수준으로 적고, 검증 스크립트에서 의존 검사를 포맷·테스트보다 먼저 돌린다. 검증 스크립트는 실패 시 0이 아닌 종료 코드를 반환하고 통과한 뒤에만 커밋한다.
10. 금지 사항(보호 브랜치 직접 push·force push, 지시 없는 커밋·MR·머지, 시크릿 기록, 미확인 값의 사실 기재)을 권한 설정(deny)과 지침에 함께 둔다. 이슈 번호 없는 커밋은 막고 이슈 생성을 먼저 요청한다.
11. 템플릿 항목은 삭제하지 않고 해당 없으면 "해당 없음"으로 쓴다. 빈 디렉터리는 `.gitkeep` 으로 남긴다.
