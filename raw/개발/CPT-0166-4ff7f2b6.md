# 함수 포인터 상태 디스패치 테이블의 범위 검사

## Definition

상태값을 인덱스로 함수 포인터 배열을 호출하는 디스패치(`(*table[state])(ctx, msg, type)`)는 상태값이 유효 범위 안이고 해당 칸이 NULL 이 아님을 호출 전에 검사해야 한다. 검사가 없으면 초기화 직후 값, 미정의 인덱스, 메모리 오염이 곧바로 크래시나 임의 주소 호출로 이어진다.

## Evidence

- 사례: 테이블 크기 12, 유효 인덱스 1~8, 0 번과 9~11 번은 NULL 이었고 호출부 네 곳 모두 검사 없이 호출했다.
- 도달 조건: 풀 슬롯 재할당 직후 `memset` 으로 state=0 인 상태에서 메시지가 먼저 도착, 미정의 상태값(NULL 호출), 테이블 크기 이상 값(배열 범위 밖 읽기 → 임의 주소 호출), 다른 버그(무경계 복사)로 state 필드가 오염된 경우.
- 수정: `is_valid_state()` 같은 헬퍼로 범위와 NULL 을 함께 검사하고 모든 호출부에 적용한다. 수정량이 작고 효과가 커서 우선 처리 대상으로 분류됐다.
- 같은 맥락: 이벤트 종류마다 다른 구조체를 같은 포인터로 받아 캐스팅하면 타입 혼동이 생기므로 메시지 종류별로 case 를 분리한다.
