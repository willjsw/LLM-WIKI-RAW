# 엔티티 리팩토링을 AI 태스크로 나눌 때 함께 넣을 횡단 작업

## Purpose

엔티티 구조를 바꾸는 작업을 여러 태스크로 나눠 AI에 맡길 때, 각 태스크가 빌드와 DB를 깨뜨리지 않도록 계획 단계에서 횡단 작업을 함께 넣는다.

## Steps

1. 작업 시작 전 `git status`로 미커밋 변경을 확인하고 먼저 정리·커밋한다. 섞이면 태스크별 커밋 의미가 깨진다.
2. 현재 빌드가 통과하는지 확인한다. 삭제된 클래스를 아직 참조하는 코드가 있으면 이미 깨져 있을 수 있다.
3. 코드의 엔티티와 DB 마이그레이션 스크립트가 일치하는지 확인하고, 태스크마다 대응하는 마이그레이션 changeSet을 같은 커밋에 넣는다(또는 별도 태스크로 명시한다).
4. 매 태스크 커밋 전에 빌드 통과를 조건으로 건다.
5. 외부 API 경로 변경처럼 호환성에 영향을 주는 항목은 리팩토링 범위와 분리해 별도 결정 항목으로 올린다.
6. 실행 전에 AI에게 계획을 검토시켜 결정이 필요한 항목 목록을 받고, 결정을 먼저 확정한 뒤 태스크를 생성한다.
