# HTTP 로 호출한 작업의 시간 예산은 서버가 집행한다

## Definition

자식 프로세스는 `process.destroy()` 로 죽일 수 있지만, HTTP 로 호출한 작업은 호출처가 커넥션을 끊어도 서버 계산이 계속된다. 그래서 작업 시간 예산(deadline)은 서버가 스스로 집행하고, 호출처 read timeout 은 그보다 길게 두어 '서버 응답 불능'만 잡는 최후 방어선으로 쓴다.

## Evidence

- 값의 출처를 하나로: `deadline = timeout − margin`, `read timeout = timeout`. 잡 메타의 timeout 하나만 고치면 양쪽이 같이 따라간다.
- margin 은 응답 직렬화·왕복 비용이라 잡과 무관하게 전역 설정으로 둔다. timeout ≤ margin 이면 0 이하가 되므로 하한을 1초로 클램프하고 경고한다.
- deadline 을 안 보내면 호출처가 timeout 을 올려도 서버는 자기 기본값만 써서 부분 집계가 영구히 해소되지 않는다.
- margin 이 0 이면 서버가 정상 종료 직전 read timeout 이 먼저 터져 TIMEOUT 오탐이 난다.
- deadline > read timeout 이면 호출처는 끝났다고 기록했는데 서버는 계속 돌아(좀비) 실행 슬롯을 쥐고 다음 복구 요청을 막는다. margin > 0 이면 deadline < timeout 이 항상 성립해 이 상황이 구조적으로 생기지 않는다.
- 남은 시간은 `time.monotonic()` 기준으로 재 NTP 보정에 흔들리지 않게 한다.
