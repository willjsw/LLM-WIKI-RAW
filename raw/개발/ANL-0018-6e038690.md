# SIP 부하테스트 콜 누락과 PRACK 미처리 가설

## Analysis

SIPp로 정확히 1,000콜을 발생시켰는데(최대 동시 400콜) 브리지 로그의 인입 건수가 약 120건 적었고, 같은 콜이 동시에 인입될 때 Reject가 났다. 동시 200콜 설정에서는 실패 없이 배정돼 단순 처리량 문제는 아니라고 판단했다.

가설: UDP 위의 SIP는 전송 계층이 재전송하지 않으므로 SIP 계층이 응답을 재전송한다. 신뢰성 있는 임시 응답(100rel)을 쓰면 PRACK을 받아야 재전송이 멈추는데, 테스트 시나리오가 PRACK을 처리하지 않아 재전송이 계속되고, 재전송된 메시지가 중복 인입으로 처리돼 Reject·누락이 났을 수 있다.

확인 방법(추정): SIPp 시나리오에 PRACK 처리를 넣거나 100rel을 끄고 같은 조건으로 재시험, 패킷 캡처에서 재전송 여부 확인. 원인은 확정되지 않았다.
