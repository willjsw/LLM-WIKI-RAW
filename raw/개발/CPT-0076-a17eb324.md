# HotSpot의 락 최적화 3단계와 Mark Word

## Definition

HotSpot JVM은 대부분의 객체에 경합이 없다는 점에 착안해 락을 Biased Lock(같은 스레드의 반복 획득, CAS 없음) → Light-Weight Lock(경합 없음, CAS 1회) → Heavy-Weight Lock(경합 발생 시 OS Mutex)의 3단계로 계층화한다. 락 상태는 객체 헤더의 Mark Word에 기록된다.

## Evidence

- 모든 객체는 Mark Word와 Class Address 두 헤더(각 1 word)를 가지며, 배열은 길이 헤더가 하나 더 있다
- Mark Word는 락 상태, GC 상태(age, forwarding), 해시코드를 겸용한다. 락이 걸리면 원래 해시코드는 Lock Record나 Monitor로 옮겨진다

| Biased | Tag | 상태 |
|---|---|---|
| 0 | 00 | Light-Weight Locked(Lock Record 주소) |
| 0 | 01 | Unlocked |
| 0 | 10 | Heavy-Weight Locked(Monitor 주소) |
| 0 | 11 | Marked for GC |
| 1 | - | Biased(스레드 ID) |

- Light-Weight Lock을 얻으면 Mark Word가 스레드 스택 프레임으로 옮겨진다(Displaced Mark)
- Biased Lock은 Java 6부터 기본 활성화되었고 `-XX:+UseBiasedLocking`으로 제어한다
- Age 필드는 객체가 Eden과 Survivor를 오간 횟수로, 승격(Promotion) 판단에 쓰인다
