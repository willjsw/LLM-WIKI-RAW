# 배포된 스크립트의 변조는 막기보다 해시로 감지

## Analysis

**문제.** 설치형 도구가 프로젝트에 관리 스크립트와 고정 CLI 사본을 평문으로 깔고, 매니페스트는 경로 목록뿐이었다. 검사·진단은 생성 파일만 비교해 관리 스크립트·가드·CLI 사본을 고쳐도 아무것도 알리지 않았다.

**구조적 결함.** 검사하는 쪽이 검사받는 쪽 안에 있다. pre-commit 훅과 검증 스크립트가 프로젝트 안 CLI 사본을 부르고 전역 CLI 도 그 사본에 위임(execv)하므로, 사본을 고치면 모든 검사가 고친 쪽 기준으로 돈다.

**판단.** 파이썬 도구는 바이너리(zipapp 등)로 만들어도 쉽게 풀린다. 변조 방지는 비용 대비 효과가 없으므로 목표를 **감지**로 잡는다.

**방안.**
- 렌더 시 매니페스트에 관리 파일과 고정 사본의 `sha256  경로` 를 기록한다.
- 검사·진단은 해시가 다르면 "modified managed file" 로 보고한다(생성물 일치·해시 검사는 0.24초 수준으로 저렴해 커밋마다 돌려도 된다).
- 매니페스트가 커밋되므로 변조가 diff 리뷰에서도 드러난다.
- 전역 CLI 는 위임 전에 자기가 가진 같은 버전 템플릿 해시와 대조해 검사자 자신이 바뀌었는지 확인한다.
- 같은 뿌리의 문제로, 사용자가 관리 디렉터리에 넣은 파일은 매니페스트에 없어 나중에 같은 이름의 관리 파일이 추가되면 경고 없이 덮인다. 덮어쓰려는 파일이 이전 매니페스트에 없으면 멈추고 알리며, 프로젝트용 스크립트 자리를 관리 디렉터리와 분리한다.
